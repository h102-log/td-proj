# 세컨드 브레인(.brain) — 영향도 그래프와 설계·장애 히스토리 검색 (2026-11-09)

## 질문

사용자 2026-11-09 요청: 코드 의존성 추적(Graph)과 설계·장애 히스토리 검색(Memory)을 하는 로컬 세컨드 브레인(`.brain/brain.db` + CLI + SKILL.md)을 만든다. 목표는 셋이다.
① 공통 함수·API 수정 때 N단계로 이어진 화면·배치·테스트를 빠뜨리지 않고 grep 왕복을 줄인다.
② 장애 대응·예외 처리로 들어간 방어 로직을 이유(Why)를 모른 채 지우는 사고를 막는다.
③ 색인·질의가 수 초 안에 끝나고, 파일 1~2개짜리 국소 작업에서는 부르지 않는다.
정적으로 못 잇는 곳은 억지로 맞추지 말고 «미확인»으로 따로 보이며, 효과가 낮은 영역은 빼자고 제안해도 된다고 했다.

## 확인한 것

**코드베이스.** Godot 4.7.2 + GDScript다(요청서 예시의 컨트롤러·서비스·쿼리 매퍼 구조가 아니다). `src` 37파일 14,925줄인데 `battle.gd` 4,763줄·`battle_view.gd` 4,176줄·`hud.gd` 1,487줄에 몰려 있다. 평가 GDScript 23,137줄 + pytest 래퍼, `tools` 9,508줄, 그림 PNG 약 1,300개.
- 호출 경계: `const Battle := preload("res://src/sim/battle.gd")` 별칭과 타입 없는 필드(`var battle`)·매개변수가 대부분이다. sim(서비스) → ui(화면)·봇(`tools/balance/autoplay.gd`)·평가 스위트로 번진다.
- 이미 있는 추적 장부: SPEC 문장 578개(§3.1 문장 대조 줄 참조 3,291개), EV 802개(근거 문장·테스트 파일·개정 1,098행), 코드 주석의 SPEC ID 3,382줄, `ponytail:` 메모 35곳, `[동작]/[이유]` 블록 11곳.
- SPEC.md는 한 줄이 최대 17,497자이고 3,000자 넘는 줄이 33개라 `grep S114 SPEC.md`만으로도 출력이 크게 불어난다.

**git.** 처음 받은 복제는 얕았다(186커밋, 10/28부터). `git fetch --unshallow`로 777커밋(10/11~)을 받았다. 제목은 «무엇 — 내용 (S·I·EV ID, 범위 S299~S302)», 본문은 «- 파일·함수: 이유» 꼴이고, 장애 수정은 «EV372 고침 — …(main에서부터 red였다)»처럼 쓴다.

**어디로 번지나(co-change).** src/sim을 고친 비병합 커밋 119개 가운데 100개(84%)가 ui를, 23개(19%)가 봇을, 16개(13%)가 save.gd를, 37개(31%)가 locale을 함께 고쳤다. battle.gd와 battle_view.gd는 118번 중 83번 같이 바뀌었다.

**만든 것.** `.brain/build`(약 3초) · `.brain/query impact|callers|find|unresolved|stats` · `.brain/why`(질의 0.13~0.22초) · `.claude/skills/codebase-brain/SKILL.md`.
- 색인: 파일 360(GDScript 126) · 심볼 5,184 · 엣지 43,851(확정 21,477 · 추론 13,773 · 동적 388 · 미확인 8,213). 미확인 지점 3,048곳은 범주별로 남겼다(SKILL.md 표).
- 심볼 id는 `경로#이름`, 안쪽 클래스는 `경로#Enemy.guard`다.
- 질의 때 파일 지문·HEAD·브레인 소스를 보고 오래됐으면 스스로 다시 만든다.

**실전 검증(2026-11-09, 이 세션).** 기준선은 에이전트가 하는 방식이다: 이름 grep → 맞은 줄의 둘러싼 함수 → 그 이름 grep, 3단계까지. 함수를 찾으려고 파일을 여는 비용은 grep 쪽에 세지 않았다(grep에 유리한 가정).

- **why** `repair_cost`: grep 방식은 12회 · 11,514자(§3.1 범위 grep만 4,637자)였다. 브레인은 1회 · 3,186자이고, SPEC 문장 6개와 변경 이력, 지키는 EV, «I85는 지키는 EV가 없다» 경고, 도입·변경 커밋의 이유 줄을 낸다.
- **커밋 맥락**: 함수 줄 히스토리(`git log -L`)가 가장 정확했다. `repair_cost`는 도입(d122aeb)과 ×1.25 변경(03cbfbc) 두 개를 찾았다. 문자열 증감(`git log -S`)은 다른 파일에 호출을 더한 커밋 6개를 섞고 정작 03cbfbc를 놓쳤다. 메시지 검색(`--grep`)은 `_taken`의 도입 커밋을 놓쳤다.
- **추론 엣지 정밀도**: 무작위 표본 42개(호출 27 · 필드 15)를 원문 줄과 대조해 42개 모두 맞았다. 표본은 «이은 것이 맞나»만 보고 «빠뜨린 것»(재현율)은 위 표의 grep 대조로 봤다.
- **한국어 검색**: «성문 핑퐁» → S135·쿨타임 커밋·`GATE_LOCK` 주석·결정 인사이트(0.14초). «공병 비켜서» → I24와 구현 함수 `_step_aside`.

## 판단 (Claude 의견)

- **1순위는 sim → ui·봇·테스트 연결부 그래프로 했다.** 근거는 위 co-change 84%·19%다. CLAUDE.md «작업 중에는 바뀐 스위트만»을 지키려면 «어느 스위트가 바뀐 코드에 닿나»를 알아야 하는데, 이 질문에 바로 답한다. 테스트는 «SPEC 연결(§3.1 + 주석 ID → EV) / 허브를 거치지 않는 3단계 안 / 그 밖(커밋 전 전체 pytest)»으로 나눈다. `repair_cost` 기준으로 돌릴 스위트가 23개에서 8개로 줄었다.
- **why는 같은 MVP에 넣되 새로 만들지 않고 이미 있는 장부를 이었다.** 이유: §3.1·주석 ID·커밋 형식이 이미 정밀해서, 이어 붙이기만 해도 효과가 크다.
- **뺀 영역(ROI가 낮다):** `art/`·`audio/` 바이너리(참조 엣지만 둠), `tools/art`·`tools/audio` 생성기의 호출 그래프(독립 도구, 코드 상수와의 짝은 주석에만 있음), `*_research/`·`enemy_guide/`(외부 조사 자료, 채택된 결정은 SPEC에 있음), `handoff/`(세션 인수인계라 커밋·SPEC과 겹치고 낡음).
- **억지로 잇지 않은 곳:** 타입 없는 받는 쪽의 같은 이름 후보, Callable 변수, 문자열 함수 이름(`call`·`has_method`), `%s` 경로 틀, 리플렉션(`get_property_list`·`set(키, …)`), 봇의 실행 중 코드 생성, 사전 문자열 키. 범주·이유·확인법은 SKILL.md «미확인 연결» 표에 있다. 리플렉션과 코드 생성은 이름 대응으로 잇되 «동적»으로 표시한다.
- **허브:** 15파일 넘게에서 불리는 함수(`build`·`step`·lib.gd `run` 등 19개)와 엔진 콜백(`_process`)을 허브로 두었다. 허브를 그대로 펴면 거의 모든 스위트가 «영향»으로 나와 좁혀 주는 효과가 사라진다(grep 3단계가 55~62파일로 폭발한 것과 같다).

## 남은 일

- **ambiguous 2,456곳 줄이기.** 남은 대부분이 타입 없는 매개변수(`func can_cast(h, slot)`)다. 호출 지점 인자의 타입을 매개변수로 넘기는 분석을 넣으면 줄어들 것으로 본다(추론, 아직 재지 않음). 대신 빌드가 1초 남짓 늘어날 것으로 보여 MVP에서는 뺐다.
- **사전 문자열 키(1,259곳).** 저장 형식(save.gd)·스테이지 사전·`*_KINDS` 표의 키는 지금 수만 센다. 키 이름 단위로 잇는 것은 다음 후보다.
- **전체 pytest를 이 세션에서 돌리지 못했다.** Godot 실행 파일 내려받기·실행이 이 세션의 권한 설정에서 막혔다. 바뀐 파일이 `.brain/`(Godot이 건너뛰는 점 폴더)·`.claude/skills/`·`.gitignore`·이 문서뿐이라 게임 평가가 읽는 파일은 없다. 로컬에서 `pytest` 한 번으로 확인한다. 브레인 자체 테스트(`python -m pytest .brain/tests -q`)는 15개 모두 통과했다.
- 난이도·밸런스 측정은 하지 않았다(CLAUDE.md, 사용자 몫).
