## 1. 9-slice(나인패치) 픽셀 프레임 설계 규칙과 프레임 패밀리

### Takeaway
Godot의 9-slice는 "모서리 고정 + 변은 한 축으로 늘이기/반복 + 가운데는 두 축으로 늘이기/반복"이며, 픽셀 아트에서는 (1) 모서리 여백에 장식·외곽선·하이라이트를 전부 넣고, (2) 변 띠를 "진행 방향으로 단면이 일정한" 1픽셀 패턴으로 그려 늘여도 왜곡이 없게 하거나, 무늬가 있으면 TILE + 이음매 없는 주기로 그리고, (3) TILE_FIT은 피하는 것이 핵심이다. 상태별(normal/hover/pressed/disabled/focus) 스타일박스는 Godot Button이 각각 따로 받는다.

### Cited Findings
- StyleBoxTexture는 "A texture-based nine-patch StyleBox ... performs a 3×3 scaling of a texture, where only the center cell is fully stretched." — [Godot StyleBoxTexture](https://docs.godotengine.org/en/stable/classes/class_styleboxtexture.html)
- StyleBoxTexture AxisStretchMode: `STRETCH` = "Stretch the stylebox's texture. This results in visible distortion unless the texture size matches the stylebox's size perfectly." / `TILE` = "Repeats the stylebox's texture to match the stylebox's size according to the nine-patch system." / `TILE_FIT` = "Unlike TILE, the texture may be slightly stretched to make the nine-patch texture tile seamlessly." 기본값은 `axis_stretch_horizontal/vertical = 0`(STRETCH). — [Godot StyleBoxTexture](https://docs.godotengine.org/en/stable/classes/class_styleboxtexture.html), [StyleBoxTexture.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/StyleBoxTexture.xml)
- NinePatchRect AxisStretchMode 설명: STRETCH "may cause the texture to be distorted", TILE "won't cause any visible distortion. The texture must be seamless for this to work without displaying artifacts between edges.", TILE_FIT "will also stretch the texture to make sure each tile is visible in full. This may cause the texture to be distorted, but less than STRETCH." — [Godot NinePatchRect](https://docs.godotengine.org/en/stable/classes/class_ninepatchrect.html)
- **문서 내부 불일치**: NinePatchRect 클래스 설명은 "it tiles the texture's edges horizontally or vertically, tiles the center on both axes, and leaves the corners unchanged"라고 하지만, 실제 `axis_stretch_horizontal/vertical`의 기본값은 `0`(STRETCH)이다. 즉 기본은 '늘이기'이므로 타일을 원하면 명시적으로 TILE로 바꿔야 한다. — [NinePatchRect.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/NinePatchRect.xml)
- NinePatchRect `patch_margin_*`: "A margin of 16 means the 9-slice's bottom corners and side will have a height of 16 pixels. You can set all 4 margin values individually to create panels with non-uniform borders." `region_rect`: "If you're working with an atlas, use this property to define the area the 9-slice should use." `draw_center`: false면 테두리만 그림. NinePatchRect의 `mouse_filter` 기본값은 2(Ignore). — [NinePatchRect.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/NinePatchRect.xml)
- StyleBoxTexture `texture_margin_*`: "A higher value means more of the source texture is considered to be part of the left border of the 3×3 box. This is also the value used as fallback for StyleBox.content_margin_left if it is negative." `expand_margin_*`: "Expands the ... margin of this style box when drawing, causing it to be drawn larger than requested." `region_rect`는 AtlasTexture로 감싼 것과 같다. — [Godot StyleBoxTexture](https://docs.godotengine.org/en/stable/classes/class_styleboxtexture.html)
- StyleBox `content_margin_*`(기본 -1): "Increasing this value reduces the space available to the contents ... If this value is negative, it is ignored and a child-specific margin is used instead ... a Button respects this content margin for the textual contents of the button." — [StyleBox.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/StyleBox.xml)
- Button은 `normal`, `hover`, `pressed`, `hover_pressed`, `disabled`, `focus` 스타일박스를 따로 받는다. `focus`는 "displayed over the base StyleBox, so a partially transparent StyleBox should be used ... A StyleBox that represents an outline or an underline works well for this purpose ... disabling the focus visual effect will harm keyboard/controller navigation usability". 아이콘–글자 간격 `h_separation` 기본 4. — [Button.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/Button.xml)
- StyleBoxFlat `anti_aliasing`(기본 true): "draws a small ring around the edges, which fades to transparency ... only noticeable when using rounded corners or skew." "When using beveled corners with 45-degree angles (corner_detail = 1), it is recommended to set anti_aliasing to false to ensure crisp visuals". `corner_detail = 1`은 "chamfered corners". — [StyleBoxFlat.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/StyleBoxFlat.xml)
- 픽셀 대화창 예: 16×16 px 타일로 NinePatchRect를 구성하고 가로·세로 모두 Tile로 두어 "the tiles are not stretched, but auto-tiled one next another when you resize the panel." — [itsjavi blog](https://blog.itsjavi.com/how-to-use-tiles-for-your-dialog-box-borders-in-godot-the-ninepatchrect-component)
- (검색 요약으로만 확인, 신뢰 중간) 9-slice 인셋은 "large enough to fully contain the corner art, but small enough that there is still a flat strip of edge and a flat center to stretch"; 단순 픽셀 UI는 16×16·24×24·32×32 원본으로 충분. — [generalistprogrammer: nine-slice scaling explained](https://www.generalistprogrammer.com/tutorials/nine-slice-scaling-explained)
- 로컬 관찰: 요청자 HUD는 9-slice 텍스처가 아니라 코드로 만든 `StyleBoxFlat`(테두리 `set_border_width_all(1)`, `shadow_size = 1`)을 쓰며, 프로젝트 전역 Theme 파일(`gui/theme/custom`)은 없다(`src/ui/hud_theme.gd` 36~51행, `project.godot`에 `[gui]` 절 없음). — [local: C:/Users/bhy99/td-proj/src/ui/hud_theme.gd]

### Inferences
- **모서리 크기 정하기**: 모서리 여백 = 반복되지 않는 테두리 요소 전체의 폭(외곽선 1px + 베벨/하이라이트 1px + 안쪽 그림자 1px + 모서리 장식). 3~4px 프레임이면 `texture_margin`도 3~4. 모서리가 장식적이면 그 장식을 다 덮는 폭으로 하고, 남은 변 띠는 1px 이상만 있으면 된다.
- **변을 왜곡 없이 늘이는 요령**: 변 띠가 진행 방향으로 단면이 똑같은(가로 변이면 모든 열이 같은 색 순서) 그림이면 STRETCH와 TILE의 결과가 같아 왜곡이 생기지 않는다. 리벳·나뭇결·점선처럼 무늬가 있으면 TILE을 쓰고, 무늬 주기 P가 끊김 없이 이어지게 그린 뒤 패널 크기를 `모서리×2 + n×P`로 맞춘다. 그렇지 않으면 끝에서 잘린 타일이 보인다. TILE_FIT은 타일을 조금씩 늘이므로 픽셀 폭이 고르지 않게 되어 픽셀 아트에는 맞지 않는다(위 문서의 "slightly stretched" 근거).
- **가운데 칸**: 단색이면 STRETCH로 충분하다. 디더나 질감이 있으면 TILE을 쓴다. 반투명 배경은 `draw_center=false` 프레임 + 별도 반투명 단색(또는 StyleBoxTexture의 `modulate_color`)으로 나누면 프레임 테두리는 불투명하게 유지할 수 있다.
- **홀수·짝수 크기**: 가운데 정렬(텍스트·아이콘·위쪽 가운데 보석 장식)은 `(상자폭 − 내용폭)`이 홀수면 0.5px 위치가 생긴다. 9-slice 자체에는 '가운데 장식' 칸이 없으므로, 가운데 장식은 별도 노드로 올리고 상자 폭과 장식 폭의 홀짝을 맞춘다.
- **expand_margin vs content_margin**: 바깥 그림자·발광·포커스 링처럼 레이아웃 밖으로 삐져나오는 픽셀은 `expand_margin`으로 그리면 버튼 클릭 영역과 정렬이 바뀌지 않는다. 글자가 베벨에 붙지 않게 하는 안쪽 여백은 `content_margin`으로 명시한다(음수면 texture_margin으로 대체되므로, 테두리가 3px일 때 글자도 테두리에 바짝 붙는다).
- **프레임 패밀리 제안(추론)**: 한 아틀라스(`region_rect`)에 기본 패널(두꺼운 프레임) / 보조 패널(얇은 프레임) / 툴팁(1px 외곽선 + 어두운 반투명 가운데) / 버튼 normal·hover(테두리 1단 밝게)·pressed(그림자 빼고 내용 1px 아래로 — `content_margin_top`을 1 늘리고 bottom을 1 줄임)·disabled(명도 대비를 낮춤)·focus(외곽선만 있는 반투명 상자)를 둔다. 외곽선 색과 모서리 모양(예: 1px 깎은 모서리)은 패밀리 전체에서 같게 한다.
- **StyleBoxFlat를 계속 쓸 경우**: 둥근 모서리(radius>0)는 AA 링이 화면 해상도로 그려져 도트가 뭉개진다. 픽셀 느낌을 원하면 radius 0, 또는 `corner_detail=1` + `anti_aliasing=false`(1px 깎은 모서리)로 둔다. `shadow_size` 그림자가 부드러운 그라데이션인지는 이번에 문서로 확인하지 못했다(아래 Gaps). 손으로 그린 9-slice 텍스처(StyleBoxTexture)로 바꾸면 하이라이트·그림자·모서리 장식을 도트 단위로 정할 수 있다.

### Gaps
- saint11·Lospec 등 픽셀 아티스트가 쓴 9-slice 전용 튜토리얼(모서리 크기 수치 규칙)은 찾지 못했다. 위 설계 규칙의 상당 부분은 엔진 문서의 동작 설명에서 끌어낸 추론이다.
- StyleBoxFlat `shadow_size`의 그림자 모양(번짐 여부)과 canvas_items 배율에서 생기는 결과는 문서로 확인하지 못했다.

## 2. Godot 4 구현: NinePatchRect vs StyleBoxTexture, Theme·타입 변형, 기본 폰트·크기

### Takeaway
재사용하는 UI 스킨은 노드(NinePatchRect)가 아니라 Theme 안의 StyleBoxTexture로 만들고, 프로젝트 설정 `gui/theme/custom`에 Theme 하나를 걸어 기본 폰트(`default_font`)와 기본 크기(`default_font_size`)를 정한다. 그런 다음 "제목 라벨·보조 패널·툴팁" 같은 변형은 타입 변형(`theme_type_variation`)으로 나누는 것이 Godot의 정석 구조다.

### Cited Findings
- `gui/theme/custom`: "Path to a custom Theme resource file to use for the project (.theme or generic .tres/.res extension)." `gui/theme/custom_font`: "Path to a custom Font resource to use as default for all GUI elements of the project." — [ProjectSettings.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- `Theme.default_font` / `Theme.default_font_size`(기본 -1, "Values below 1 are invalid") — 테마에 값이 없으면 `ThemeDB.fallback_font_size`(기본 **16**)를 쓴다. — [Theme.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/Theme.xml), [ThemeDB.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ThemeDB.xml)
- 폰트 크기는 폰트 리소스가 아니라 노드에서 정한다: "font sizes are no longer defined in the font itself" — 노드의 Theme Overrides > Font Sizes. — [Godot: Using Fonts](https://docs.godotengine.org/en/stable/tutorials/ui/gui_using_fonts.html)
- `gui/theme/default_font_antialiasing` 등 `gui/theme/default_font_*` 설정은 엔진 기본 폰트에만 적용된다: "This setting does not affect custom Fonts used within the project. Use the Import dock for that instead". — [ProjectSettings.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- 타입 변형은 "work like normal theme types, but instead of being self-sufficient and standalone they extend another, base type." 테마 에디터에서 Type 추가 → Base Type 지정. 노드는 Inspector의 Theme Type Variation으로 쓴다. 이 드롭다운에는 프로젝트 전역 테마의 변형만 나온다. — [Godot: Theme type variations](https://docs.godotengine.org/en/stable/tutorials/ui/gui_theme_type_variations.html)
- `Control.theme_type_variation`: "When set, this property gives the highest priority to the type of the specified name. This type can in turn extend another type, forming a dependency chain ... The project-level Theme and the default Theme are checked last." — [Control.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/Control.xml)
- NinePatchRect는 그 자체로 Control 노드(장식 판 하나)이고, StyleBoxTexture는 "in a way similar to NinePatchRect"인 StyleBox 리소스다. 그래서 Panel·Button·PanelContainer·Tooltip 등 테마 항목에 넣을 수 있다. — [Godot StyleBoxTexture](https://docs.godotengine.org/en/stable/classes/class_styleboxtexture.html), [Godot NinePatchRect](https://docs.godotengine.org/en/stable/classes/class_ninepatchrect.html)
- 로컬 관찰: 요청자 HUD는 `hud_theme.gd`의 `make(font_size)`가 코드로 Theme을 만들고 `t.default_font_size = font_size`를 넣는다. 그와 별개로 여러 곳에서 `add_theme_font_size_override("font_size", 7|8|9)`로 크기를 따로 덮어쓴다(8: 9곳, 7: 3곳, 9: 3곳 + 변수 크기 다수). — [local: C:/Users/bhy99/td-proj/src/ui/hud_theme.gd, src/ui/*.gd]

### Inferences
- 권장 구조: `ui_theme.tres` 하나 → `gui/theme/custom`에 연결 → `default_font = Galmuri…`, `default_font_size = 디자인 크기(또는 그 정수배)` → Panel/PanelContainer/Button/TooltipPanel에 StyleBoxTexture → 변형 `PanelSub`, `PanelTooltip`, `LabelTitle`, `LabelSmall`, `ButtonIcon` 등. 이렇게 하면 크기·색·여백 값이 Theme 한 곳에 모인다. 노드마다 흩어진 `add_theme_*_override`가 서로 다른 크기·여백을 만드는 것이 "제각각인 UI"의 흔한 원인이다.
- NinePatchRect는 배경 장식 판(예: 대화창 뒤 장식)처럼 한두 번 쓰는 곳에만 쓰고, 상태가 있는 버튼·컨테이너는 StyleBoxTexture로 만든다. Button은 상태마다 StyleBox를 받기 때문이다.

### Gaps
- 타입 변형이 Godot 4.x 마이너 버전 사이에 바뀌었는지는 대조하지 않았다(4.0부터 있는 기능으로 알지만 확인하지 않음).

## 3. Godot 4 픽셀 폰트 설정 (FontFile 임포트, 비트맵 폰트, 외곽선·그림자, 오버샘플링)

### Takeaway
TTF 픽셀 폰트는 Antialiasing **Disabled**, Hinting **None**, Subpixel Positioning **Disabled**, MSDF·Mipmaps **끔**으로 임포트하고, 크기는 반드시 **디자인 크기의 정수배**로만 쓴다. 비트맵(BMFont·이미지) 폰트는 Scaling Mode를 **Integer Only**로 둔다. 기본값은 마이너 버전마다 달라졌으니(4.4 subpixel, 4.5 oversampling, 4.7 hinting) 값을 명시해 두는 편이 안전하다.

### Cited Findings
- 공식 지침: "Fonts that have a pixel art appearance should have bilinear filtering disabled by changing the Rendering > Textures > Canvas Textures > Default Texture Filter project setting to Nearest." / "Fonts that have a pixel art appearance should have their subpixel positioning mode set to Disabled." / "The font size must also be an integer multiple of the design size (which varies on a per-font basis)." — [Godot: Using Fonts](https://docs.godotengine.org/en/stable/tutorials/ui/gui_using_fonts.html)
- Antialiasing: "Disabled: Most suited for pixel art fonts, although you do not have to change the antialiasing from the default Grayscale if the font file was well-created and the font is used at an integer multiple of its intended size. If pixel art fonts have a bad appearance at their intended size, try setting subpixel_positioning to Disabled instead." — [ResourceImporterDynamicFont.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ResourceImporterDynamicFont.xml)
- Hinting: "controls how aggressively glyph edges should be snapped to pixels"; None = "Smoothest appearance, which can make the font look blurry at small sizes"; 새 모드 "Light (Except Pixel Fonts): Disabled for pixel style fonts (each glyph's contours contain only straight horizontal and vertical lines), Light for other fonts." — [ResourceImporterDynamicFont.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ResourceImporterDynamicFont.xml)
- Subpixel positioning: "This should be set to Disabled for fonts with a pixel art appearance." 옵션에 "Auto (Except Pixel Fonts)"가 있다. 서브픽셀은 처음 래스터라이즈를 느리게 해 "can cause stuttering during gameplay". — [ResourceImporterDynamicFont.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ResourceImporterDynamicFont.xml)
- **버전 차이(임포트 기본값)**: hinting 기본값은 4.3·4.4·4.5·4.6에서 `1`(Light), **4.7에서 `3`(Light (Except Pixel Fonts))**. subpixel_positioning 기본값은 4.3에서 `1`(Auto), **4.4부터 `4`(Auto (Except Pixel Fonts))**. — [RIDF 4.3](https://raw.githubusercontent.com/godotengine/godot/4.3/doc/classes/ResourceImporterDynamicFont.xml), [RIDF 4.4](https://raw.githubusercontent.com/godotengine/godot/4.4/doc/classes/ResourceImporterDynamicFont.xml), [RIDF 4.6](https://raw.githubusercontent.com/godotengine/godot/4.6/doc/classes/ResourceImporterDynamicFont.xml), [RIDF 4.7](https://raw.githubusercontent.com/godotengine/godot/4.7/doc/classes/ResourceImporterDynamicFont.xml)
- MSDF: "crisp rendering at any size ... resizing the font in real-time without any performance penalty"(기본 false). FontFile 문서: MSDF에서는 "font hinting is unavailable". Mipmaps는 축소용이며 "Only enable this setting if you actually need it." — [RIDF (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ResourceImporterDynamicFont.xml), [Godot FontFile](https://docs.godotengine.org/en/stable/classes/class_fontfile.html)
- `keep_rounding_remainders`(기본 true): "when aligning glyphs to the pixel boundaries rounding remainders are accumulated to ensure more uniform glyph distribution. This setting has no effect if subpixel positioning is enabled." — [RIDF (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ResourceImporterDynamicFont.xml)
- `allow_system_fallback`(기본 true): 글리프가 없으면 시스템 폰트로 대체한다. "This makes supporting CJK characters or emoji more straightforward". `fallbacks` 배열로 대체 폰트를 직접 지정할 수 있다. — [RIDF (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ResourceImporterDynamicFont.xml)
- **버전 차이(oversampling)**: 4.3의 임포트 옵션 `oversampling`은 "overrides the oversampling factor for the font ... In most cases, this should be left at 0.0". 4.5부터는 "overrides the oversampling factor of the viewport this font is used in. - 요청자 폰트 임포트는 이미 맞다. 남은 문제는 **크기**다. Galmuri7의 디자인 크기는 8px(§6)이므로 `font_size` 7·9는 "디자인 크기의 정수배" 규칙을 어긴다. 그런 글자는 획 두께가 들쭉날쭉하고 일부 픽셀이 빠지거나 겹친다. 8(또는 16)만 쓰고, 더 큰 글자가 필요하면 다른 디자인 크기의 폰트(Galmuri9=10px, Galmuri11=12px, Galmuri14=15px)를 쓴다.

## 4. 스트레치 모드: canvas_items vs viewport(+integer)가 글자·스프라이트를 어떻게 그리는가

### Takeaway
공식 문서는 픽셀 아트에 **viewport + integer**를 권장한다. 요청자의 **canvas_items + integer(640×360→1280×720, 2배)**는 모든 것을 1280×720에서 직접 그린다. 그래서 (1) 동적 폰트는 오버샘플링으로 화면 해상도(×2)에서 래스터라이즈되고, (2) 정점·트랜스폼 스냅은 화면 픽셀 기준이라 UI·글자가 '아트 반 픽셀'에 놓일 수 있다. 픽셀 폰트를 디자인 크기의 정수배로만 쓰면 글자 밀도는 아트와 같다. 하지만 크기 7·9, 둥근 StyleBoxFlat, 비정수 위치·크기 트윈은 아트보다 고운 '섞인 픽셀'을 만든다.

### Cited Findings
- 정의(4.3~4.7 동일 문구): `"canvas_items"`: "everything is rendered directly at the target resolution. 3D is unaffected, while in 2D, there is no longer a 1:1 correspondence between sprite pixels and screen pixels, which may result in scaling artifacts. Recommended for most games that don't use a pixel art aesthetic, although it is possible to use this stretch mode for pixel art games too (especially in 3D)." / `"viewport"`: "The size of the root Viewport is set precisely to the base size ... The scene is rendered to this viewport first. Finally, this viewport is scaled to fit the screen ... Recommended for games that use a pixel art aesthetic." — [ProjectSettings.xml 4.3](https://raw.githubusercontent.com/godotengine/godot/4.3/doc/classes/ProjectSettings.xml), [ProjectSettings.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- **버전 차이**: canvas_items 설명에 "This is the default for projects created starting in Godot 4.7."가 붙었다(4.6 XML에는 없음). — [ProjectSettings.xml 4.6](https://raw.githubusercontent.com/godotengine/godot/4.6/doc/classes/ProjectSettings.xml), [ProjectSettings.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)

### Inferences
- **요청자 설정에서 실제로 일어나는 일(2배일 때)**:
  1. 렌더링은 1280×720에서 하고, 640×360 좌표를 2배로 펴서 그린다. 텍스처(스프라이트·9-slice)는 Nearest로 2×2 블록이 되어 선명하다.
  2. 동적 폰트는 오버샘플링 = 뷰포트 배율(2)이라, 크기 8 Galmuri7은 16px로 래스터라이즈된다. 글자 1픽셀 = 화면 2×2로 아트와 밀도가 같다. 반면 크기 9는 18px(글자 1픽셀 = 2.25px), 크기 7은 14px(1.75px)로 래스터라이즈되어 획 폭이 2px·3px로 섞인다. "아트보다 고운, 고르지 않은 글자"가 되는 직접적인 원인이다.
  3. 정점 스냅은 셰이더에서 캔버스 트랜스폼(스트레치 포함)을 곱한 뒤 하므로, 1280×720 화면 픽셀 기준이다(셰이더 코드 + 문서의 "canvas_items는 서브픽셀 이동 가능" 서술에서 추론). 그래서 좌표 x.5(기본 단위)에 놓인 라벨·패널·아이콘은 아트 격자에서 화면 1px(=아트 반 픽셀) 어긋난다. 가운데 정렬, 컨테이너 비율 분배, 비정수 트윈에서 흔히 생긴다.
  4. StyleBoxFlat 둥근 모서리의 AA, 회전, 0.5 단위 스케일 같은 벡터 효과는 화면 해상도로 그려져 아트(2px 블록) 위에 1px짜리 디테일이 섞인다.
- **(a) 전부 아트 픽셀로 맞추는 UI(가장 확실)**: `stretch/mode = viewport`, `scale_mode = integer`, Nearest, `snap_2d_transforms_to_pixel = true`(vertices는 끄기, 문서 권장), 폰트는 디자인 크기 그대로(Galmuri7=8, Galmuri11=12). 모든 것이 640×360 격자에 놓이므로 섞인 픽셀이 원천적으로 없다. 대가: 카메라 스크롤·트윈·파티클이 1아트픽셀 단위로 끊긴다(GDQuest "very jagged"). 8px 한글은 640×360에서 정보 밀도가 낮다. 비픽셀 폰트는 쓸 수 없다.
- **(a′) canvas_items를 유지하면서 규율로 맞추기**: 폰트 크기를 디자인 크기 정수배로만 두고, UI 위치·크기를 정수 기본 단위로 반올림하고(가운데 정렬 홀짝 맞추기), StyleBoxFlat 둥근 모서리를 없애고, 스케일 트윈을 정수 배율로만 쓴다. 문서상 transforms 스냅을 권하지만, canvas_items에서는 어느 쪽 스냅이든 화면 픽셀 기준이라 아트 격자를 보장하지 않는다. 위치 반올림을 코드에서 해야 한다.
- **(b) 저해상도 게임 + 고해상도 UI(셀레스트식 이원화)**: 루트는 canvas_items(1280×720)를 유지한다. 게임 월드는 `SubViewportContainer(stretch=true, stretch_shrink=2)` 안의 SubViewport(640×360)에서 그리고 컨테이너 필터를 Nearest로 둔다. UI는 그 위 CanvasLayer에서 1280×720 기준으로 그린다. 이때 UI 폰트를 '화면 1px = 글자 1px'로 쓰면(예: Galmuri11 12px을 배율 없이) 아트보다 2배 고운 픽셀 글자가 된다. 섞여 보이지 않으려면 **UI 전체를 한 밀도로 통일**해야 한다(UI 9-slice 프레임도 1:1 화면 픽셀로 그리거나 일관되게 2배). 한 화면에 1배 글자와 2배 프레임이 섞이면 아마추어처럼 보이기 쉽다(추론). 셀레스트가 실제로 어떻게 구성했는지는 이 노트의 범위 밖이다(다른 조사 담당).
- 현재 2배 고정 창(1280×720)에서는 #86563(창 크기를 바꿀 때 흐려짐)이 덜 문제일 수 있다. 다만 전체화면에서 3배·4배가 되면 오버샘플링 배율도 바뀌므로 그 배율에서 캡처로 확인해야 한다.

### Gaps
- canvas_items에서 `Window` 스트레치 트랜스폼이 셰이더의 `canvas_transform`에 포함된다는 것은 엔진 C++ 코드(Viewport의 stretch/global canvas transform 합성)를 직접 열어 보지는 않았다. 셰이더 코드와 문서 서술로 추론했다.
- #86563이 정확한 정수 배율(2·3배)에서도 생기는지는 이슈에서 확인되지 않았다.
- `snap_2d_vertices_to_pixel`이 Godot 4.x에서 폐기 예정인지(포럼 사용자의 기억)는 공식 출처로 확인되지 않았다. 공식 문서는 "Prefer only enabling [transforms]"까지만 말한다.

## 5. 움직임을 픽셀 단위로 깨끗하게(정수 위치 트윈, 정수 배율 스케일)

### Takeaway
UI 애니메이션은 위치를 **정수 기본 단위로 반올림**해 보간하고, 스케일은 1↔2 같은 정수 배율이나 미리 그린 프레임 교체로 하며, 페이드(`modulate.a`)처럼 형태를 바꾸지 않는 효과를 우선 쓴다. 엔진 스냅에만 맡기면 canvas_items에서는 화면 픽셀(아트 반 픽셀) 단위로 움직인다.

### Cited Findings
- 위치 스냅은 소수점을 버려 선명하게 하지만 "at the cost of less smooth movement, especially when Camera2D smoothing is enabled." — [ProjectSettings.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- 분수 배율은 "will lead to uneven pixel scaling"(픽셀 폭이 고르지 않게 됨). — [Godot: Multiple resolutions](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)
- "Control scaling should only be used for animation purposes, not for persistent scaling." (Calinou) — [GitHub #86563](https://github.com/godotengine/godot/issues/86563)
- viewport 모드에서는 트윈·파티클이 "very jagged". — [GDQuest pixel art setup](https://www.gdquest.com/library/pixel_art_setup_godot4/)
- Control은 기본으로 가장 가까운 픽셀에 스냅된다(`gui/common/snap_controls_to_pixels` = true). — [ProjectSettings.xml (master)](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- 포럼 보고: transforms 스냅을 켜면 CharacterBody2D 움직임이 덜 부드러웠고, Camera2D process callback을 Physics로 바꾸자 나아졌다(사용자 보고, 비공식). — [Godot Forum: Snap 2D Vertices vs Transforms](https://forum.godotengine.org/t/difference-between-snap-2d-vertices-to-pixel-and-snap-2d-transforms-to-pixel/78642)

### Inferences
- 구현 패턴(추론): `tween_method(func(v: Vector2): panel.position = v.round(), from, to, 0.15)`처럼 보간값을 받아 반올림해 넣는다. 그러면 ease 곡선을 써도 매 프레임 정수 기본 단위에 놓인다. canvas_items에서는 이렇게 해야 아트 격자에 맞는다(엔진 스냅은 화면 픽셀 기준).
- 팝업 연출은 scale 0.9→1.0 대신 (1) 위치를 4~8px 아래에서 올리기 + 알파 페이드, (2) 2~3장짜리 픽셀 프레임 애니메이션, (3) 1배↔2배 정수 스케일 중에서 고른다. 회전은 쓰지 않는다.
- 숫자 카운트업·게이지는 채움 폭을 정수 픽셀로 반올림하고(게이지 채움 = `floor(ratio × 폭)`), 9-slice 게이지라면 최소 폭을 모서리×2 이상으로 둔다.

### Gaps
- Godot 공식 문서에서 "UI 트윈을 정수 위치로" 권하는 직접적인 문장은 찾지 못했다. 위 패턴은 스냅·배율 문서에서 끌어낸 추론이다.

## 6. 상업적 사용이 가능한 한글 픽셀 폰트와 라틴 픽셀 폰트

### Takeaway
Galmuri(OFL 1.1, 8·10·12·12·15px 계열, 공식 사이트 기준 전 변형이 현대 한글 11,172자)가 게임 UI용으로 가장 갖춰진 선택지다. Neo둥근모(OFL 1.1, 16px 배수 권장, 상업 사용 명시 허용)는 굵고 레트로한 대안이다. 라틴 전용으로는 Daniel Linssen의 m5x7(CC0 표기)·m3x6("free to use with attribution")이 엔진 크기 16의 배수로 쓰인다. 요청자가 쓰는 Galmuri7.ttf를 직접 파싱해 보니 한글 11,172자가 모두 들어 있었다.

### Cited Findings
- Galmuri 변형별 픽셀 크기: Galmuri14 = 15px(11pt), Galmuri11 = 12px(9pt), Galmuri11 Bold = 12px, Galmuri11 Condensed = 12px, Galmuri9 = 10px(7.5pt), Galmuri7 = 8px(6pt). 라이선스 OFL-1.1. — [GitHub quiple/galmuri](https://github.com/quiple/galmuri)
- Galmuri 공식 사이트: "모든 폰트가 한글 완성자 11,172자를 지원합니다." 라이선스는 "SIL 오픈 폰트 라이선스 1.1", © 2019–2025 Lee Minseo, 닌텐도 DS의 폰트 디자인에서 영감을 받았다. — [quiple.dev/font/galmuri](https://quiple.dev/font/galmuri); **충돌**: GitHub README 표에는 Galmuri7에 대해 "4,358 Hangul Syllables"(Adobe-KR-0·1 기준) 각주가 있다 — [GitHub quiple/galmuri](https://github.com/quiple/galmuri)
- 로컬 실측(요청자 `art/fonts/Galmuri7.ttf`, cmap 직접 파싱): 한글 완성형 U+AC00–D7A3 **11,172/11,172**, ASCII 인쇄 가능 95/95, Latin-1 보충 96, Latin Extended-A 128, 가나 187, CJK 한자 6,360, 호환 자모 52. 메트릭: unitsPerEm 800, hhea ascent 800 / descent −100 / lineGap 200 → 8px에서 ascent 8 + descent 1 (+ lineGap 2)px. — [local: C:/Users/bhy99/td-proj/art/fonts/Galmuri7.ttf]
- Galmuri는 JIS X 0208의 CJK 통합 한자 6,355자, KS X 1001의 호환 한자 268자(Galmuri11·9)를 넣었고, 히라가나·가타카나도 있다(Galmuri11 Bold 제외). — [GitHub quiple/galmuri](https://github.com/quiple/galmuri)
- Neo둥근모: 도스용 비트맵 한글 글꼴 '둥근모꼴'(김중태, 퍼블릭 도메인 배포)을 트루타입으로 변환했다. "SIL Open Font License 1.1 하에 배포"되며 "상업적 또는 비 상업적 용도로 어디서든 자유롭게 이용"할 수 있다. 변형은 Neo둥근모 / Neo둥근모 Code(합자) / Neo둥근모 Pro(가변폭, 커닝, v1.020). 글꼴 자체의 유료 재판매는 금지. — [GitHub neodgm/neodgm](https://github.com/neodgm/neodgm), [neodgm.dalgona.dev](https://neodgm.dalgona.dev/)
- Neo둥근모 가이드: "글꼴의 크기는 16픽셀의 배수로 맞추어 주시기 바랍니다." 배수가 아니면 외곽선이 픽셀 경계 사이에 떨어져 흐려진다. "볼드체나 이탤릭체 등의 글꼴 스타일을 적용하지 마세요." — [neodgm guides](https://neodgm.dalgona.dev/guides.html)
- Fusion Pixel Font(TakWolf): 8px·10px·12px, 고정폭/비례폭(비례폭 권장: "如无特殊需求，建议优先使用「比例模式」"), 언어별 변형 latin·zh-Hans·zh-Hant·zh-HK·zh-TW·ja·ko. 한국어 글리프는 Galmuri에서 가져왔다("8、10、12 像素韩语相关字形"). 폰트는 OFL-1.1, 빌드 프로그램은 MIT. 고정폭 모드는 "字体基线略微偏高"(기준선이 약간 높음). — [GitHub TakWolf/fusion-pixel-font](https://github.com/TakWolf/fusion-pixel-font)
- m5x7(Daniel Linssen): 에셋 라이선스 "Creative Commons Zero v1.0 Universal" 표기 + "free to use but attribution appreciated". "use font size 16, 32, 48, etc". 메트릭 ascender +7, descender −2, x-height +5. 대소문자·다수 악센트 문자·숫자·기호. 파일은 m5x7.ttf. — [itch.io managore/m5x7](https://managore.itch.io/m5x7)
- m3x6(Daniel Linssen): "free to use with attribution", "use font size 16, 32, 48, etc", ascender +6, descender −2, x-height +5, m3x6.ttf. — [itch.io managore/m3x6](https://managore.itch.io/m3x6)

### Inferences
- "네이티브 크기"는 엔진에 넣을 font_size 값이다. Galmuri7→8, Galmuri9→10, Galmuri11→12, Galmuri14→15, Neo둥근모→16, m5x7/m3x6→16(TTF em이 16 '폰트 픽셀'로 설계됨). 640×360 기본 해상도에서 본문 Galmuri11(12px)은 한 줄 높이가 약 14~16px이다. 툴팁·수치는 Galmuri9(10px), 맵 위 작은 숫자는 Galmuri7(8px)처럼 **역할별로 폰트 자체를 바꾸는 것**이 크기 7·9를 섞어 쓰는 것보다 선명하다.
- 한/영 혼용: Galmuri에는 자체 라틴(ASCII·Latin-1·Latin Ext-A)이 있어 한 폰트로 두 언어가 된다. m5x7 같은 라틴 폰트를 영어 UI에 따로 쓰면 한국어판과 영어판의 글자 높이·기준선이 달라지므로, 레이아웃을 언어마다 따로 확인해야 한다(추론).
- 줄 간격: Galmuri7 메트릭(8px에서 ascent 8 + descent 1)에 Godot Label 기본 `line_spacing` 3을 더하면 약 12px 줄 높이가 된다(Godot가 hhea lineGap을 쓰는지는 미확인). 촘촘한 HUD라면 line_spacing을 0~2로 테마에서 정한다(추론).

### Gaps
- Galmuri7의 한글 수 충돌(README 4,358 vs 사이트·로컬 파일 11,172): 로컬 파일은 11,172자 모두에 글리프가 매핑되어 있다. 다만 4,358자만 손으로 다듬고 나머지는 조합 생성인지 등 품질 차이는 확인하지 못했다. 로컬 파일 버전도 확인하지 않았다.
- Neo둥근모의 한글 수록 범위(11,172자 여부)는 가져온 페이지에 적혀 있지 않았다(문자 목록 페이지는 열지 않음).
- Fusion Pixel / Ark Pixel의 크기별 한글 수록 수는 info 문서를 열지 않아 확인하지 못했다. Ark Pixel 자체는 조사하지 못했다.
- 줄 높이에 Godot TextServer가 hhea lineGap을 포함하는지는 확인하지 못했다.
