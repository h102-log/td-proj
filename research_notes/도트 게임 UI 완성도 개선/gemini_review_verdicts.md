# Gemini 평가 판정: «도트 게임 UI 완성도 개선» 보고서

대상: `reports/도트 게임 UI 완성도 개선.md`의 PR #353 판(main `187ca8e`). 아래 행 번호는 그 판 기준이다. Gemini 원문은 같은 폴더의 `gemini_review.md`(4 Argon, 사고 수준 보통, 2026-11-15)다. Gemini 점수 7.5/10, 지적 16개. 검증자 둘(근거·실무)의 판정이 갈린 F3·D1·D2·C1·P1은 Godot 4.7 소스(`button.cpp`·`label.cpp`·`texture_rect.cpp`·`style_box_flat.cpp`·`FontVariation.xml`)와 저장소 코드를 직접 열어 보고 정했다. 대비 값도 WCAG 식으로 다시 계산했다.

## 총평

16개 가운데 수용 0, 부분 수용 11, 기각 5, 판정 불가 0이다. 받아들이는 것은 결론 일부다. L7의 «홀수면 왼쪽 정렬» 지우기, C2(월드 팔레트 공유)를 권장으로 낮추기, L1에 1px 예외 두기, L9를 «먼저 고칠 순서»에 넣기, 2부 10의 성격 바로 적기, 아이콘+숫자 세로 정렬 규칙, Stardew 배율 맥락 한 구절, 1부의 작은 중복 정리다. 근거까지 맞은 지적은 드물다. 대신 검증하는 과정에서 Gemini가 짚지 못한 보고서 자체의 결함이 나왔다. 첫째, `LINE` 상수는 게이지 바탕·신뢰 점·빈 칸 점선을 겸하는데 보고서는 «LINE만 바꾼다»고 적었다. 둘째, A8의 눌림 `content_margin` ±1이 L1과 부딪친다. 셋째, I293 ④가 정한 장비 줄 1px을 대책 없이 «미달»로만 두었다. 넷째, Label·Button의 가로 가운데 정렬이 반 픽셀을 만든다고 잘못 적었다. 기각하는 지적은 F1·F2·F4·F6·C4다.

Gemini가 사실을 잘못 안 곳은 다음과 같다.
- 측정·출처
  - XAG 101은 글자 높이를 대문자 높이가 아니라 디센더~어센더(body height)로 잰다.
  - 1.5배 줄 간격은 WCAG 1.4.12가 아니라 XAG 101(두 줄 넘는 글)과 WCAG 1.4.8에서 왔다.
  - Galmuri11 한글의 전진폭은 12px라 40×12=480이 맞다.
- 보고서를 잘못 읽은 곳
  - 보고서는 FontVariation 사용을 금지하지 않았다. 막은 것은 FontVariation으로 크기를 키우는 일 하나다.
  - Into the Breach를 640×360 게임이라고 한 적도 없다.
- 엔진·코드
  - Godot 4.7은 Label·Button의 가로 가운데 오프셋을 정수로 내린다. 그래서 «0.5 px에 놓인다»는 전제부터 틀렸다.
  - «색 3줄·5분»도 틀렸다. `LINE`이 테두리 말고 네 곳을 겸한다.
  - 제목 화면 버튼은 엔진 기본 버튼이 아니라 HudTheme 상자다.
  - Galmuri7·9는 세로 가운데 정렬 어긋남이 0px라 «1~2px 뜸»은 과장이다.
- 문서 분량: 중복은 6회가 아니라 4회다. 줄일 수 있는 양도 1% 안팎이라 «20~25%»는 근거가 없다.
- 근거가 없거나 틀린 주장
  - «72px 패널에 안 들어간다»
  - «Theme 변형이 수십 개 생긴다»
  - «#0c0f16·#1F141A는 UI 전용»
  - «한국어 BmFont 원본이 2배»

## 보고서에 반영할 수정(우선순위 순)

1. [P1] 대조표 C3 행(341행)과 A3 행(354행)의 «첫 수정»에 경고를 붙인다.
   - `LINE`이 겸하는 곳: 보스·진행 막대 바탕(`hud.gd:621,1076`), 신뢰 점 꺼짐(`hud_evac.gd:83`), 빈 영웅 칸 점선(`hud.gd:1567`), 건설 칸 평상시 테두리(`hud_build.gd:117,127`).
   - 그러니 테두리용 상수를 먼저 나누고 테두리만 3:1 이상으로 올린다. 새 테두리색이 HOVER보다 밝으면 HOVER도 함께 올린다.
   - C3 행에 덧붙인다: 아래 패널은 `framed()`가 이미 6b7280(PANEL 위 3.74:1)이다. 위 띠·툴팁·토스트 테두리를 바꾸면 S241의 «그대로다»를 바꾸는 사용자 결정이 된다.
2. [P1] «먼저 고칠 순서» 3단계(321행)를 둘로 나눈다.
   - 3a: LINE 나누기와 테두리만 올리기. hex가 SPEC·평가에 없고 아이콘 시트와 무관하니 2단계 앞으로 당겨도 된다.
   - 3b: C1·C6·C9 hex 정리와 순색 교체. «SPEC·평가 개정이 따른다»는 문구는 3b로 옮긴다.
   - 색 후보 ④(362행)에 이유를 더한다: «CELL을 PANEL 대비 3:1(예: 5b637a)로 올리면 DIM/CELL이 2.27:1로 C4에 못 미친다».
3. [C1] L7(172~175행)의 통과 기준을 바꾼다.
   - 지울 문장: «`(부모 폭 − 내용 폭)`이 짝수다. 그러지 못하면 왼쪽 정렬로 바꾼다».
   - 넣을 내용: 글자(Label·Button 가로)는 엔진이 정수로 내리므로 가운데 정렬을 그대로 두고, 홀수면 여백이 1 기준 px 다를 뿐이다. 홀짝이나 반올림은 내림이 없는 곳에서만 맞춘다(TextureRect `STRETCH_KEEP_CENTERED`·`KEEP_ASPECT_CENTERED`, Button 글자 세로, `draw_*` 직접 계산). 왼쪽 정렬로 바꾸지 않는다.
   - L7의 Godot 줄과 2부 2(97행)의 «가운데 정렬한 글자의 내부 오프셋»도 같은 뜻으로 고친다.
4. [C3] 3부 C2(191~193행)를 «권장(추론)»으로 낮춘다.
   - 통과 기준을 «UI 색을 `palettes.json`에 등록한다. 맞는 색이 없으면 ui 램프를 더해도 된다»로 바꾼다.
   - 색상 이동 조건은 권장 문장으로 옮기고, Slynyrd의 «There is no law…»를 함께 적는다.
   - 예외를 둔다: C4·C9 글자 대비나 A6 외곽선을 팔레트 안에서 맞출 수 없으면 UI 전용 색을 더한다. 바탕은 아트 외곽선 151a26과 같은 단을 쓰지 않는다.
   - 색 후보 ③(362행)에 «지금 PANEL 14161c도 151a26과 1.04:1이라 팔레트 공유 탓이 아니다»를 더한다. ④는 «테두리 7a86a0이 3.77:1 이상이라 C3을 통과한다»로 고친다.
   - 대조표 C2 행(340행)의 판정을 «권장 미충족»으로 바꾼다.
5. [C2] L1(148~149행)에 1 기준 px 예외 두 가지를 넣는다.
   - (가) 눌림처럼 내용을 1px 옮기는 상태 차이. A8(305행)의 `content_margin` ±1을 여기에 잇는다.
