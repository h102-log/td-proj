# 04. 이 프로젝트에 적용할 점

01~03의 근거를 이 프로젝트에 맞춰 해석한 문서다. 근거 ID가 없는 문장은 추론이다. WBS·SPEC·코드는 고치지 않았고, 결정은 모두 사용자가 한다.

## 1. AI 공개와 아트 결정 (WBS 2.14, 10/21 시험)

사실:
- WBS 2.14대로 Claude가 아트를 만들면 공개 대상이다. 캡슐과 상점 스크린샷도 포함된다 [F-03].
- 사용자는 2026-10-12에 공개를 받아들였다. 이 문서는 그 결정을 다시 다투지 않는다.

근거가 가리키는 것:

1. **대가는 평점보다 리뷰 수에 나타난다.** 첫 달 리뷰 −52.6% [V1-01], 리뷰 100개 도달률 55% [F-01]에 비해 평점 차이는 작다 [V1-06]. TD 장르도 방향이 같다 [N1-19].
   - 픽셀 게임은 AI 공개율이 낮다 [N1-01] [N1-18]. 그래서 이 장르에서는 AI 표기가 더 눈에 띌 수 있다(추론).
2. **불만은 음성과 눈에 띄는 아트에 몰렸다** [M1].
   - 이 게임은 음성을 쓰지 않는다면 가장 큰 불만원은 해당하지 않는다(추론).
   - 남는 것은 첫 화면, 메인 메뉴, 캡슐처럼 처음 보이는 아트다 [M1].
   - 아이콘·UI·BGM·번역에만 AI를 쓴 게임은 부정 리뷰에서 언급되지 않았다 [M1]. 표본이 작다.
3. **겉모습만으로 의심받은 픽셀 사례가 있다.**
   - Widget Inc.는 한 리뷰어가 겉모습을 보고 의심한 뒤 공개 문구로 확인했다 [N1-11].
   - Postal: Bullet Paradise는 스프라이트 의혹으로 취소됐다 [N1-15].
   - Schrodinger's Cat Burglar는 AI가 아닌데도 캡슐을 교체했다 [N1-17].
   - 10/21 시험 판정 때 함께 볼 수 있다.
4. **공개 문구는 흥행작 쪽 패턴과 실패작 쪽 패턴이 갈린다.** 상관관계다.
   - 흥행작 쪽: 길고 구체적이다(중앙값 22단어). '보조' 표현과 사람 검수를 내세운다 [V1-10] [V1-11].
   - 실패작 쪽: 10단어 이하 한 줄이 많다 [N1-05].
   - 출시 뒤에 공개를 추가한 게임은 '공개 시점' 비판을 받았다 [N1-10] [M1]. 리뷰어 주장이고 검증하지 않았다.
   - 문안 초안은 [art_source_research/04](../art_source_research/04_policy_and_rights.md)에 있다.
5. **코딩을 어떻게 말할지는 따로 정할 일이다.**
   - 공개 의무는 없다 [F-03].
   - 그래도 플레이어 56%는 코딩 도구도 공개해야 한다고 답했다 [F-04].
   - Rogue: Genesia는 AI 코딩 공지 하나로 한 달 부정 리뷰가 몇 배로 늘었다 [N1-09]. 누적 평점은 유지됐다.
   - 아트를 공개하면 어차피 상점에 AI 표기가 붙으므로, 코딩 사용만 숨길 실익은 작다(추론).

## 2. 상점 페이지 (WBS 8.3~8.5, 12/1 이후)

| 항목 | 근거가 말하는 것 | 근거 |
|---|---|---|
| 태그 | 히트작 6/7이 Tower Defense를 1위에 두었다. Valve는 태그가 중요하다고 밝혔다. 태그 칸을 다 채우지 않는 페이지가 많다(업체 자료, 신뢰도 낮음) | [M2] [N2-14] [Q2-f4] |
| 짧은 설명 | 첫 문장에 '짓고 지킨다' 또는 장르 이름을 담는다. 67~309자 | [M2] |
| 스크린샷·트레일러 | 8~12장, 트레일러 1개가 관습이다. 노출 순위 요인은 아니다 | [M2] [N2-13] |
| 캡슐 | 썸네일 크기에서 글자가 안 읽히는 캡슐이 흔하다(업체 자료). 규격은 [art_source_research/06](../art_source_research/06_fonts_and_capsule.md) | [Q2-f4] |
| AI 공개 | 캡슐과 스크린샷에 AI 아트가 들어가면 공개 대상이다 | [F-03] |

## 3. 첫 5분 (11/9~30 수정·추가 계획 때)

| 배울 점 | 근거 |
|---|---|
| 첫 웨이브는 '방금 배운 것 하나로 정확히 막히는' 크기로 만든다 | [Q2-b1] |
| 튜토리얼이 끝난 뒤에도 팁으로 가르친다. 팁은 한 번만 또는 써 볼 때까지만 띄우고, 개수를 제한하고, 끌 수 있게 한다 | [N2-03] [N2-04] |
| 튜토리얼이 가르치지 않은 편의 기능은 놓친다. 이 게임에는 드래그 선택이 있다(WBS R7) | [N2-02] |
| 화면 텍스트는 짧게(한 번에 약 8단어), 새 요소는 띄엄띄엄 낸다 | [Q2-a2] [Q2-a3] |
| 초보용 기본 선택지는 무난하되 약간 약하게 둔다 | [N2-05] |
| 첫 판은 짧게, 초반은 개발자에게 '바보같이 쉽게', 쉬운 건물부터 해금한다 | [N2-06] [N2-08] |
| 메타 진행은 초보의 결정 마비를 줄이지만, 설계한 조우를 쉽게 만들 수도 있다. 이 게임에는 라운드를 넘어 이어지는 도전 구조가 있다(WBS R7) | [N2-01] [Q2-b6] |

데모를 만든다면: 쉽게, 중앙 플레이 시간 30~90분, 정식판 일부만 넣고 잠긴 것을 보여 주고, 상점 링크를 둔다 [Q2-c1]~[Q2-c7]. 데모를 낼지는 정하지 않았다.

## 4. 개발 방식 — 회고 패턴과 대조

'이 프로젝트에 있는 것'은 저장소 파일로 확인한 사실이다(2026-10-18). '남는 위험'은 추론이다.

| 회고 패턴 ([03 §2](03_vibe_coded_games.md#2-되풀이-패턴)) | 이 프로젝트에 있는 것 | 남는 위험 |
|---|---|---|
| 빠른 시작, 멈춘 중반 | `WBS.md` 일정과 범위, R5(밀리면 일정을 늘린다) | 11/9~30 추가 기간에 시스템이 서로 얽히는 때 |
| 반복 프롬프트로 안 고쳐져 롤백·새 세션 | handoff NAP(`next/`)로 세션 전환, `EVAL.md`와 `tests/eval`의 실행 가능한 판정 | – |
| 회귀(한쪽만 고침, 고치다 깨뜨림) | `tests/eval`·`tests/unit`(.gd 46개), specgate 평가 | 테스트가 덮지 않는 화면·연출 |
| 별도 검증 장치가 문제를 잡음 | 봇 측정(`tools/balance/autoplay.gd`, `sweep.py`), 평가 스펙 | – (이미 '잘 된 쪽'과 겹친다) |
| 맥락 한계, 긴 파일 | `src/sim/battle.gd`가 1,530줄이다(소스 .gd 14개, 합계 2,505줄) | 회고에서는 '긴 스크립트를 못 읽음'(C2), '수천 줄'(C1)이 정체의 신호였다. 지금 문제가 있다는 근거는 없고, 지켜볼 지표다 |
| Godot에서 AI 생산성이 낮음 | Godot 4로 진행 중이고, headless 테스트가 돈다 | C1은 Godot에서 JS로 옮겼지만, 이 프로젝트는 이미 그 단계를 지났다 |
| 아트 일관성 | `art_direction_research`의 팔레트·규격, 10/21 시험 | Claude 아트를 세션마다 따로 만들 때(C1의 첫 번째 큰 문제) |
| 보안·성능을 AI가 스스로 챙기지 않음 | – | 성능(유닛 수가 늘 때)은 [art_direction_research/05](../art_direction_research/05_godot_rendering.md) 측정표가 다룬다 |

## 5. 일정 관련 사실 (WBS는 고치지 않았다)

- **등록비 후 대기 기간:** WBS 8.1은 21일(→ 12/22)이다. 그런데 Steam Direct 안내 페이지에는 30일로 적혀 있다 [N2-22]. 30일이면 12/1에 결제했을 때 가장 빠른 출시일은 12/31이고, 지금 묶는 제약(커밍순 2주 → 12/24)보다 늦다.
- **Next Fest:** 2027년 2월 회차(2/22~3/1)에 참가하려면 출시가 3/1 이후여야 한다. 1/10까지 등록하고, 상점 페이지를 공개하고, 데모를 내야 한다 [N2-17] [N2-19]. 12월에 출시하면 참가할 수 없다. WBS R4(커밍순 2주로는 위시리스트가 안 쌓인다)와 관련된 사실이다.
- **상점 심사 기간:** 출시 문서는 보통 3~5영업일, 커밍순 문서는 7영업일 전에 요청하라고 한다 [N2-20] [N2-21]. WBS 8.4는 7영업일로 잡았다.
