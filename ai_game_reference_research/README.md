# AI·바이브코딩 게임 참조 조사

이 프로젝트(Godot 2D 도트 수성 디펜스, AI 코딩으로 개발, 2026-12 스팀 등록)가 다른 사람들이 AI·바이브코딩으로 만든 게임에서 무엇을 참조할지 조사했다. 질문은 셋이다.

1. AI 사용을 공개한 스팀 게임은 어떤 반응을 받고, 불만은 어디에 몰리나?
2. 잘된 인디 디펜스 게임은 상점 페이지와 첫 5분을 어떻게 짰나?
3. 바이브코딩 게임 회고에서 되풀이되는 실패 패턴과 상업 성과는?

확인 날짜는 2026-10-17~18이다. WBS·SPEC·코드는 고치지 않았다.

## 결론

**참조할 가치가 가장 큰 것은 '스팀이 AI 공개 게임을 어떻게 대하는가'다.**
- AI로 코드만 짜면 공개 의무가 없다 [F-03]. 하지만 WBS 2.14 잠정 결정대로 Claude가 만든 아트를 빌드에 넣으면 공개 대상이다.
- 공개 게임은 여러 요인을 통제해도 출시 첫 달 리뷰가 52.6% 적고 [V1-01], 리뷰 100개 도달률이 비AI의 55%다 [F-01]. 관찰 연구라 원인으로 단정할 수는 없다. 2024~26 타워디펜스에서도 방향이 같다(리뷰 100개 이상 11.5% 대 16.7%, 통제 없음) [N1-19].
- 불만은 계속 들리는 AI 음성과 첫 화면처럼 눈에 띄는 아트에 몰렸다. 아이콘·UI·음악·번역 용도는 TD 표본의 부정 리뷰에서 언급되지 않았다 [M1]. 표본이 작다.
- 흥행한 AI 게임은 공개 문구가 더 길고 사람 검수를 내세웠다 [V1-10] [V1-11].
- 코딩도 안전지대는 아니다. AI 코딩 계획을 공지한 픽셀 게임에 부정 리뷰가 몰린 사례가 있다 [N1-09].

**상점 페이지와 첫 5분은 AI 게임이 아니라 잘된 디펜스 게임에서 배운다.**
- 히트작 7개 중 6개가 사용자 태그 1위에 Tower Defense를 두었다. 스크린샷 중앙값 10장, 트레일러 1개이고, 짧은 설명 첫 문장에 무엇을 하는 게임인지를 담았다 [M2].
- Valve는 스크린샷 수, 설명 길이, 위시리스트가 노출 알고리즘 요인이 아니라고 밝혔다. 구매·플레이와 태그가 중요하다 [N2-13] [N2-14].
- Thronefall은 튜토리얼이 끝난 뒤에도 팁으로 가르치고, 메타 진행으로 초보의 결정 마비를 줄였다 [N2-01] [N2-03].

**바이브코딩 게임 회고에서 되풀이되는 것은 '빠른 시작, 멈춘 중반'이다.**
- 프롬프트를 반복해도 안 고쳐져 롤백하고 새 세션을 열었다.
- 맥락 한계로 설계 연속성을 잃었다.
- Godot에서 AI가 고전했다. Codex Mortis는 Godot에서 JS로 옮겼다 [N3-07] [N3-09] [Q3-a2].
- 잘 된 쪽은 별도 검증 장치(적대적 분석, 두 번째 AI 검토, QA)였다 [N3-02] [N3-11].
- 상업 성과는 작거나 단발이었다 [N3-06] [N3-12].
- 이 프로젝트의 평가 스펙, 봇 측정, 인수인계는 '잘 된 쪽'과 겹친다(추론).

## 표기와 신뢰도

- 본문의 사실 문장에는 `[F-01]`처럼 주장 ID를 붙였다. ID와 출처 URL의 대응은 [99 §2](99_sources.md#2-주장-대장)에 있다.
- ID가 없는 해석에는 "(추론)"을 붙였다. 04는 해석 문서라, ID가 없는 문장은 모두 추론이다.

| 접두 | 무엇 | 검증 |
|---|---|---|
| `F-` | 1차 조사 종합 11개 | 3표 적대 검증 통과(2-1 이상) |
| `R-` | 1차 조사에서 기각된 4개 | 본문에 근거로 쓰지 않았다 |
| `V1-` | 질문 1 수치의 원문 재확인 | 보충 연구자가 원문을 대조했다 |
| `Q2-`, `Q3-` | 1차에서 뽑혔지만 검증 차례가 오지 않은 주장 | 보충 연구자가 원문을 대조했다(확인/정정/기각) |
| `N1-`, `N2-`, `N3-` | 보충 조사에서 새로 찾은 주장 | 연구자 한 명이 원문·API로 확인했다. 교차 검증은 없다 |
| `M1`, `M2` | 이 조사가 스팀 API로 직접 잰 표 | 2026-10-18 측정, 표본이 작다 |

- 출처 성격은 공식 / 1차 / 2차 / 블로그 / 포럼으로 나눴다. 판매·리뷰 영향 데이터(01)는 블로그·업체 분석이다. 동료 심사를 거친 연구는 없다.
- 1차 조사에서 기각된 주장은 [99 §3.1](99_sources.md#31-1차-검증에서-기각-r-)에 있다. 보충 조사에서 정정된 것 중 결론에 영향이 있는 것은 §3.2에 있다.

```
보충  질문별 연구자 3명: 원문 대조, 빈 곳 채우기, 스팀 API 실측(M1 · M2)
제약  보충 조사 도중 웹 검색 한도가 바닥나, 뒷부분은 알려진 URL과 스팀 API로만 진행했다
```

## 사용자 확인이 필요한 곳

결정은 하지 않았다. 자세한 것은 [04 §5](04_apply_to_this_project.md#5-일정-관련-사실-wbs는-고치지-않았다)에 있다.

- **WBS 8.1 대기 기간:** WBS는 등록비 결제 후 21일(→ 12/22)로 잡았다. Steam Direct 안내 페이지는 30일이라고 한다 [N2-22]. 30일이면 가장 빠른 출시일은 12/31이다.
- **Next Fest:** 2027년 2월 회차는 출시가 3/1 이후여야 하고, 1/10까지 등록해야 한다 [N2-19]. 12월 출시와 함께 할 수 없다. WBS R4와 관련된 사실이다.
- **10/21 아트 시험:** 픽셀 스프라이트가 겉모습만으로 AI로 의심받은 사례 [N1-11] [N1-15] [N1-17]와 공개 문구 근거 [V1-10] [V1-11]를 판정 때 함께 볼 수 있다.
- **코딩 사용을 상점이나 공지에서 어떻게 말할지:** 공개 의무는 없지만 [F-03] 반발 사례가 있다 [N1-09].

## 알려진 한계

- 판매·리뷰 영향(53%, 55%)은 관찰 연구다. AI 용도별로 나눈 분석은 없다 [V1-04].
- M1(TD AI 공개 10개)은 리뷰가 많은 게임이 둘뿐이다. 코드로 만든 픽셀 아트를 공개한 사례는 없다.
- 웹 검색 한도 때문에 Godot 기반 AI 코딩 게임의 출시 회고, Kingdom·Rogue Tower 원작자의 설계 발언을 찾지 못했다.
