# 03. 바이브코딩 게임 — 회고에서 되풀이되는 패턴과 상업 성과

질문 3에 답한다. AI 코딩으로 만든 게임의 회고에서는 무엇이 되풀이되고, 그 게임들은 얼마나 벌었나?

확인 날짜는 2026-10-18이다. Reddit은 직접 접속이 막혀 pullpush 아카이브로, X 게시물은 fxtwitter API로 읽었다.

## 요약

- **'빠른 시작, 멈춘 중반'이 가장 흔하다.** 프로토타입은 몇 시간 만에 나오지만, 시스템이 늘면 정체하거나 전면 재작성이 필요해진다. 사례 C1~C4에서 모두 나왔다.
- **같은 문제를 프롬프트로 반복해도 안 고쳐진다.** 롤백하고 새 세션을 여는 것이 공통 대응이었다(C1~C4).
- **맥락 한계로 설계 연속성을 잃는다.** 상태 머신이 약점으로 두 번 나왔다. Godot에서 AI 생산성이 낮다는 말이 세 곳에서 나왔다. Codex Mortis 개발자는 Godot으로 시작했다가 JS로 옮겼다 [N3-07].
- **잘 된 쪽은 별도 검증 장치였다.** AI에 적대적 분석을 시키거나, 두 번째 AI로 커밋을 검토하거나, 독립 테스트 페이지를 만들었다(C1, C2, C4).
- **상업 성과는 작거나 단발이었다.**
  - fly.pieter.com: 17일차 월 $87k까지 갔지만, 만든 사람 스스로 '지속 불가'로 분류했다 [Q3-b3] [N3-06].
  - Codex Mortis: 개발자 자기 보고로 앞서 해보기 직후 '수백 장' 팔렸고 [N3-12], 현재 리뷰 107개 77.6% 긍정이다 [Q3-c1].
  - Vibe Jam 2025 상위 수상작은 무료 웹게임으로 남았다 [N3-29]. 돈을 번 쪽은 주최 측이다 [N3-30].

## 1. 사례

### C1. Codex Mortis — 'AI로 100% 만든' 스팀 게임

- **개요** [Q3-c1] [Q3-c2] [F-11]:
  - 1인 개발자 GROLAF가 만들고 퍼블리셔 CRUNCHFEST가 냈다(appid 4084120).
  - 2026-03-26 앞서 해보기, 2026-09-24 정식 1.0, 가격 $3.99.
  - 공개 문구는 코드, 글, 아트, 사운드, 음악 전부에 AI를 썼다는 내용이다.
  - 이미지는 ChatGPT, 코드는 Claude Code로 만들었다. 엔진 없이 TypeScript, PixiJS, bitECS, Electron을 썼다.
- **반응** [Q3-c1] [Q3-c3]:
  - 본편: 리뷰 107개, 77.6% 긍정(대체로 긍정적). 스팀 구매자만 보면 94개, 80.9%다.
  - 데모: 159개, 66.7% 긍정(복합적).
  - 1차 검증에서 기각된 '데모 약 60%', '기계가 만든 쓰레기'는 재확인에서도 원문에 없었다 [R-3].
- **부정 리뷰가 겨냥한 곳** (직접 다중 라벨로 센 대략치) [N3-17]:
  - 데모(53개): AI·'slop' 언급 약 20(그중 약 10개는 다른 내용이 거의 없음), 게임성 약 16, UI·가독성 약 11, 성능 10, 버그 9, 사운드 9, 아트 7
  - 본편(24개): 게임성 9, 밸런스 5, AI 자체 4, UI 4, 가독성 4, 성능 4
  - 정식 출시 뒤에는 AI 자체보다 게임성, 밸런스, UI 불만이 중심이 됐다.
- **개발자 본인이 쓴 회고** (Steam 포럼, Reddit):
  - 첫 시도는 Godot이었다. AI가 고전해 진행이 몹시 느렸고, Claude의 추천으로 JS로 옮겼다 [N3-07].
  - 프로토타입은 프롬프트 하나로 나왔지만, 출시까지 전면 재작성을 두 번 했다. 몇 주간 기능을 덧붙이자 성능이 무너지고 파일이 수천 줄로 커졌다. "vibe coding builds debt faster than it builds features" [N3-08]
  - 모델 맥락 크기라는 벽에 부딪혀 아키텍처 연속성을 잃었다. "AI is a good programmer, but a poor architect". 상태 머신은 여전히 약점이다 [N3-09].
  - 버그 약 100개 가운데 상당수는 중복된 코드 경로 중 한쪽만 고친 것이었다. 개발자는 자신이 아키텍처를 안다고 밝혔다. 그래서 '개발자가 시스템을 이해 못 한다'는 주장은 기각했다 [Q3-c5] [R-4].
  - CLAUDE.md는 기초 시스템을 만든 뒤, 이미 통하는 패턴을 적어 둔 스냅샷이었다. 시스템이 20개를 넘자 짧은 지시로도 컨벤션을 따랐다 [N3-10].
  - 2~3번 시도해 안 되면 롤백하고 새 채팅을 열었다. 핵심은 AI가 아니라 QA 품질이었다고 썼다. 터미널 3개 병렬은 괜찮았지만 5개는 혼란스러웠다 [N3-11].
  - 세션 간 아트 일관성이 첫 번째 큰 문제였다. 컨셉은 ChatGPT, 품질은 Nano Banana, 정리는 PixelLab으로 나눠 썼다 [N3-13].
- **앞서 해보기 중 큰 개편:**
  - 시점을 탑다운에서 아이소메트릭으로 바꾸며 스프라이트를 전부 다시 만들었다. 9월에는 덱빌딩으로 개편했다.
  - 개편 직후 'UI를 알아볼 수 없다'는 부정 리뷰가 나왔다 [N3-16].
- **성과** (자기 보고): 데모 1만 회 이상 플레이, 중앙 플레이 시간 71분, 앞서 해보기 직후 수백 장 판매 [N3-12].

### C2. Godot 메트로배니아 — 포기한 회고 (Godot 포럼, 2026-04)

- **개요:** 1인 개발자가 두어 달 동안 약 40시간 바이브코딩하다 멈췄다 [Q3-a1].
  - 쓴 도구: Gemini(기획) → Replit → Cursor → Continue + Google AI Studio → Cline. Claude는 쓰지 않았다 [Q3-a7].
  - 5일 뒤 손으로 코딩해 계속하겠다고 번복했다 [Q3-a1].
- **빠른 시작:** 첫 3~4시간에 이동, 사다리, 스캐너, 저장/불러오기를 갖춘 프로토타입이 나왔다 [Q3-a6].
- **실패 지점:**
  - 에이전트는 한 번에 스크립트 2~3개 이상을 다루지 못했고, 긴 플레이어 스크립트를 읽어 내지 못했다 [Q3-a2].
  - Continue는 코드베이스를 망가뜨렸고, Cline은 고친 것보다 깨뜨린 것이 많았다 [Q3-a3].
  - 적·전투는 프롬프트를 거듭해도 안 고쳐지고 자주 나빠졌다 [Q3-a4].
  - AI가 만든 상태 머신은 사실상 플레이어 스크립트가 확인하는 전역 변수였다 [Q3-a5].
- **갖춘 것:** Godot·LSP·태스크 관리·GitHub용 MCP, 페르소나 분리, 기능 브랜치별 세션까지 갖췄지만 상태 머신 리팩터에서 실패했다 [N3-01].
- **잡아낸 방법:** AI에 적대적 분석을 시켜서야 지름길로 짠 코드를 찾았다 [N3-02].
- **교훈:** GDScript·Godot 지식 부족을 AI로 메울 수 없다 [Q3-a6].
- **댓글(포럼):** Claude는 아키텍처 실수가 많고, 맥락이 차면 다시 시작해야 한다. Godot에서 노드·에디터로 될 일을 코드로 과하게 짠다 [N3-31].

### C3. fly.pieter.com — 바이럴 단발

- **제작:** 2025-02 Pieter Levels가 Cursor로 약 3시간 만에 만들었다 [Q3-b1].
- **문제:** 순조로운 건 80%였고, 몇 번은 이전 버전으로 되돌려 같은 요청을 반복했다 [N3-03]. AI 코드에 XSS 구멍이 있었고, 명시적으로 점검을 시켜야 했다 [N3-04].
- **매출:**
  - 17일차 월 $87k(연 $1M 환산), 누적 플레이어 32만 명. 도구는 Cursor + Claude 3.5였다 [Q3-b3] [N3-05].
  - 무료 게임이고 수입은 게임 내 광고 슬롯, 브랜드 비행선, $29.99 F-16이었다 [Q3-b4].
  - Levels는 광고 슬롯이 갱신되는 구독이라고 했다. '구독이 아니다'라는 dev.to 서술은 반대다 [Q3-b5].
- **현재:** Levels는 이 게임을 '돈은 벌었으나 지속 불가'로 분류하고, 활동 기간을 2025년으로만 적었다 [N3-06]. '2026년 중반 월 $0'과 '13일차 $67k'는 확인하지 못했다 [Q3-b2] [Q3-b6].
- **일반화의 한계:** 팔로워 약 98만 명 계정의 결과다 [Q3-b7].

### C4. Doomscroll — 비개발자의 소품

- 약 9개월 전 GPT-4로는 실패했고, GPT-5로 2시간 만에 프로토타입이 나왔다 [N3-18].
- 그림은 말로 전달되지 않았다. 그래서 슬라이더가 달린 독립 테스트 페이지('lab')를 만들게 해 우회했다 [N3-18].
- Apple Watch용으로 옮겨 $1.99에 냈다. 미국 평점은 1건이다. 개발자는 'AI slop과 한데 묶일까' 걱정했다 [N3-19].

### C5. Vibe Jam 2025·2026

- **2025:** 공식명 Bolt Vibe Coding Game Jam 2025. 규칙은 '코드와 에셋 등의 80% 이상을 AI가 작성'이었다 [N3-20].
  - 출품 1,083개 중 2026-10-18 현재 살아 있는 것은 632개다(사이트 자체 판정) [N3-22].
  - 사전 심사에서 1,000개 이상이 약 500개로 줄었고, 상당수는 로드조차 안 됐다(검색 스니펫만) [N3-23].
  - 심사평에도 'janky', '레벨 디자인이 밋밋하다' 같은 마감 품질 지적이 있었다. 참가자 대다수는 게임을 처음 만든 사람이었다 [N3-21].
- **2026:** Cursor Vibe Jam. 규칙은 코드 90% 이상 AI 작성이다 [N3-24].
  - 1위 작품은 Claude Code, Tripo3d, Suno, ElevenLabs를 썼다고 적었다 [N3-25].
  - 출품 945개가 자유 기입한 도구 언급 횟수: Claude 379, Cursor 209, Codex 182 [N3-26].
  - 심사위원 Tim Soret은 '상위 20%는 아니지만 3학년 학생 수준'이라고 평했다 [N3-27].
- **후속:**
  - 2025 금·은 수상작은 상업 링크 없는 무료 웹게임으로 남았다 [N3-29].
  - 동메달 Vector Tango는 Meta Quest 혼합현실 게임으로 바뀌었다. 위시리스트·베타 단계이고 수익 수치는 없다 [N3-28].
  - 주최 측은 Vibe Jam을 '성공'으로 분류하고 월 $44K를 표기한다 [N3-30].

## 2. 되풀이 패턴

사례 2개 이상에서 나온 것만 모았다. C6은 Godot 포럼 댓글 [N3-31]로, 근거가 약하다.

| 패턴 | 근거 사례 |
|---|---|
| 몇 시간 만에 프로토타입이 나오지만 중반에 멈추거나 전면 재작성이 필요해진다 | C1, C2, C3, C4 |
| 같은 문제를 프롬프트로 반복해도 고쳐지지 않거나 나빠져, 롤백·새 세션이 필요하다 | C1, C2, C3, C4 |
| 맥락 한계: 긴 파일이나 여러 파일을 다루지 못해 아키텍처 연속성을 잃는다 | C1, C2, C6 |
| 상태 머신이 AI의 약점이다 | C1, C2 |
| Godot·GDScript에서 AI 생산성이 낮다 | C1, C2, C6 |
| AI는 구현은 잘하지만 설계는 못한다. 사람의 도메인·아키텍처 지식이 성패를 가른다 | C1, C2, C6 |
| 고치다 다른 곳을 깨뜨리거나, 중복된 코드 경로 중 한쪽만 고치는 회귀가 생긴다 | C1, C2 |
| 보안·성능 같은 비기능 요구를 AI가 스스로 챙기지 않는다 | C1, C3 |
| 아트·비주얼 일관성과 화면 가독성에 문제가 생긴다 | C1, C4 |
| 'AI 제작'이라는 꼬리표 자체가 반발이나 반발 걱정을 부른다 | C1, C2, C4 |
| (잘 된 쪽) 별도 검증 장치가 문제를 잡는다: 적대적 분석, 두 번째 AI로 커밋 검토, 독립 테스트 페이지 | C1, C2, C4 |
| 상업 성과가 작거나 오래가지 않는다: 바이럴 단발, 수백 장 수준, 무료로 남은 수상작 | C1, C3, C4, C5 |

참고: '통하는 패턴을 문서로 남기면 이후 지시가 짧아도 된다'는 C1 한 곳에서만 나와 패턴으로 세지 않았다 [N3-10].

## 3. 한계

- **검색 한도:** 조사 도중 세션 전체의 웹 검색 한도가 바닥났다. 그래서 스팀·itch.io에 낸 다른 AI 코딩 게임의 회고, 특히 Godot이나 2D 전략·디펜스 사례는 찾지 못했다.
- **표본 편향:** 회고는 크게 성공했거나 극적으로 실패한 사람이 주로 쓴다.
  - Codex Mortis 글들은 Reddit에서 홍보 성격의 글이다.
  - Vibe Jam의 도구 정보는 자기 신고다.
  - 실패한 사례 대부분은 글로 남지 않는다. 2025 출품작의 약 42%가 이미 내려간 것이 그 단서다 [N3-22].
- **숫자:**
  - Codex Mortis 판매량은 개발자 자기 보고뿐이다.
  - 리뷰 분류는 연구자 한 명이 한 번 읽고 붙인 대략치다.
