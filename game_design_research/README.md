# 3중 복합 수성 디펜스 — 규칙 아키텍처 리서치

2D 도트 다크 판타지 영지 방어 게임에서 **시설**(성벽·타워·공성 병기·함정), **용병**(배치형 일반 부대), **영웅**(네임드 정예)이 한 전장에서 충돌 없이 맞물리게 하는 구조 규칙을 조사한 결과다. 모티브는 《디펜스 게임의 폭군이 되었다》다. 수식·대미지 수치·밸런스 표는 다루지 않는다.

## 읽는 순서

시간이 없으면 1→2→3만 읽는다.

1. [06/01 핵심 설계 결정 4가지](06_prototype_decisions/01_core_design_decisions.md): 결론. 결정마다 선택지, 권장 기본값(DEC-01~14), SPEC.md 대조가 있다.
2. [04/02 성공·실패 요인](04_benchmarks/02_success_and_failure_factors.md): 선례 게임이 실제로 무너진 여섯 패턴과 개발사가 고친 방식.
3. [06/02 프로토타입 검증 체크리스트](06_prototype_decisions/02_prototype_validation_checklist.md): 그레이박스에서 "~하면 ~가 보이는가"로 확인할 항목.
4. 필요한 주제 폴더(01~05). 규칙 후보의 근거와 트레이드오프가 여기 있다.
5. [99 미해결 질문](99_appendix/open_questions.md): 근거가 끝내 비어 있는 곳과 잠정 기본값.

## 표기와 신뢰도

본문의 사실 문장에는 모두 대장 ID가 붙어 있다. ID가 없는 해석은 "(추론)"으로 표시하거나 아래 블록에 넣었다.

```
> **[규칙 후보 PREFIX-NN]** 규칙 문장
> - 근거: [대장 ID] · 트레이드오프: 얻는 것 / 잃는 것
```

| 대장 ID | 검증 방식 | 개수 | 읽을 때 |
|---|---|---|---|
| `R1-F*` | 3표 반박 검증(2/3 생존) 후 병합 | 12 | 가장 강하다. 괄호 속 분석자 해석은 사실이 아니다 |
| `R2-C*` | 2관점 재검증(원문 대조 / 독립 교차 확인) | 확인 12 · 부분 확인 47 | 부분 확인은 **수정 문장 범위 안에서만** 사실이다 |
| `R2-G*` | 보충 조사 + 1표 반박 검증 | 확인(1표) 27 · 부분 확인 21 | 검증이 가장 얕다. 이것만 근거인 규칙 후보는 약하다 |
| `R1-X*` | 3표 반박 검증에서 탈락 | 6 | **기각됨 — 인용 금지.** 05/02에 기각 사유를 정리했다 |

- 2차 검증에서는 기각이 한 건도 없었고 대부분 '부분 확인'이었다. 틀린 주장을 버렸다기보다 과장된 범위를 깎아 냈다는 뜻이다. 살아남았다고 원래 주장이 그대로 맞는 것은 아니다.
- 출처 성격(개발사 인터뷰·공식 패치 노트 / 위키 / 블로그 / 포럼·리뷰 한 건)은 본문에 함께 적었다. 포럼·리뷰 한 건에 기댄 실패 사례가 적지 않다.
- 수치는 대장의 원문 인용 칸에만 남아 있다. 출처 원문을 보존하려는 것이며 설계 제안이 아니다.

## 조사 방법

```
1차  검색 각도 5 → 출처 18 → 주장 89 추출 → 25개 3표 반박 검증(생존 19 · 기각 6) → 병합 12
2차  (가) 1차에서 검증 못 한 59개를 2관점 재검증 → 확인 12 · 부분 확인 47
     (나) 공백 4주제(KR·Thronefall·OMD / WC3·Legion TD·Iron Brigade·DD / 오라·지휘·붕괴 / 상성·지배 전략)
          × 12개 보충 조사 → 1표 검증 → 확인(1표) 27 · 부분 확인 21
문서  폴더별 작성 에이전트 → 대장 대조 검토 에이전트(과장·무인용·수치 수정) → 결정 문서 작성·검토
```

대장(`claim_ledger.md`, `sources.md`)은 스크립트가 만든 파일이라 손으로 고치지 않는다. 다시 만들려면 `99_appendix`에서 `python -I raw/build_ledger.py raw .`을 실행한다. 같은 결과가 나오는지 해시로 확인했다.

## 결론 요약

아래는 모두 **권장 기본값(설계 제안)**이며 사실 주장이 아니다. 근거와 반대 선택지는 링크한 파일에 있다.

| 결정 | 권장 기본값 | 정하지 않으면 부딪히는 것(06/01 각 결정의 x.1) |
|---|---|---|
| 1. 조작 계층 | 실시간 직접 조작은 영웅 한 명. 시설은 자동, 용병은 위치만 지정하고 교전은 AI. 일시정지는 관찰 후 보조로만 (DEC-01~03) | 용병 자율 교전 ↔ 이동 명령, 영웅 조작 ↔ 용병 미세 조작, 개입 지점 수 ↔ 입력 속도 |
| 2. 공간·교전 판정 | 경로·조준·접촉 층을 따로 판정. 저지는 1:1. 탑승형 시설은 탑승자가 있어야 사격. 하드 체크마다 다른 축의 예비 경로를 둔다 (DEC-04~07) | 저지 용량 ↔ 누수 가독성, 탑승 ↔ 시설 화력, 우회형 적 ↔ 축 투자, 하드 체크 ↔ 선택의 여지 |
| 3. 손실과 영웅 다운 | 영웅은 전투 안에서 부재 후 복귀하고, 부상 누적 비용은 전투 밖에서 청구. 영구 손실은 확률이 아니라 누적 횟수로, 캠페인 옵션으로. 다운 시 지휘 효과만 사라지고 패배는 방어 목표로만 판정 (DEC-08~11) | 용병 충원 ↔ 경제, 영웅 다운 ↔ 용병 전선, 영웅 부재 ↔ 조작 계층 |
| 4. 자원과 단계 | 단일 화폐 + 맵별 점유 상한. 영웅 레벨은 화폐가 아닌 전투 경험으로. 건설과 유료 충원은 준비 단계에만. 파괴된 시설은 잔해로 남기고 다음 준비 단계에 복구 (DEC-12~14) | 전투 중 구매 ↔ 조작 상한, 화폐 수 ↔ 딜레마, 영웅 육성 ↔ 시설·용병 |

## 사용자 확인이 필요한 곳

권장안 네 곳이 [SPEC.md](../SPEC.md)에서 사용자가 확정한 문장의 범위를 좁힌다. SPEC은 고치지 않았고 06/01에 "사용자 확인 필요"로 표시만 했다.

| SPEC 문장 | 권장안 | 무엇이 좁아지나 |
|---|---|---|
| S9 맞닿으면 멈춰 근접전 | DEC-05 1:1 저지 | 아군 하나가 적 하나만 붙잡는다. 나머지 적은 계속 걷는다 |
| S8 골드를 내면 바로 배치 | DEC-12 점유 상한, DEC-13 | 배치 수에 상한이 생기고, 유료 배치는 준비 단계에만 된다 |
| S7 빈 터 건설 | DEC-13 | 전투 중에는 건설할 수 없다 |
| S5 지점 지정 이동 | ROLE-01·CTL-02 | 이동이 시설·배치 지점 기준 반경 안으로 제한된다 |

## 알려진 한계

- **끝내 찾지 못한 근거**: WC3 Hero Defense류 유즈맵의 규칙 원문, Castle Fight, KR·OMD·Iron Brigade·DD 개발자의 의도 인터뷰, Thronefall 위키, Total War 장군 사망 수치, Northgard·CoH2 오라. → [미해결 질문](99_appendix/open_questions.md)
- **원작 근거가 얇다**: 원작 관련 규칙 후보 상당수(SRC-01~04 등)는 장면 하나를 일반화한 것이다. 원작의 피로도 서술은 확인하지 못했다.
- **결정 문서에 남은 빈칸**: 영웅이 탑승 중에 쓰러지는 경우, 적을 붙잡고 있는 영웅에게 이동 명령을 내리는 경우, 영웅을 노리는 적이 부상 누적 속도에 미치는 영향은 아직 정의되지 않았다(06/01 검토 의견).
- **파일 간 불일치 하나**: CTL-07·SF-13은 일시정지를 기본으로 권하고 DEC-03은 이를 미룬다. 결론은 DEC-03을 따른다.
- 1차에서 추출만 되고 2차 재검증에 들어가지 않은 주장이 5개 있으며, 경위는 기록에 없다.
