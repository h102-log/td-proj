# 02. 시점과 높이 — 정사각 격자를 비스듬히 내려다보기

질문: 정사각 칸 16px 격자를 비스듬히 내려다볼 때 카메라 고도각, 건물·성벽 높이, 가림, 방향 수를 어떻게 잡나.

확인 날짜는 모두 2026-10-14다. `[R-xx]` → 출처는 [99](99_sources.md)에 있다. 확인하지 못한 항목은 "확인 못 함"으로 적었다. 아이소메트릭·측면 게임의 각도는 쓰지 않았다.

## 1. 표

| 항목 | 확인한 것 | 출처 성격 |
|---|---|---|
| 카메라 고도각 | **Factorio: 45도 dimetric.** 화면의 정사각 칸 하나는 위에서 본 실제 바닥으로 1 × 1.414(√2)다 [R-13] | 1차(개발 블로그) |
| 다른 해법 | **젤다 ALBW: 카메라는 바로 위, 물체만 하나씩 뒤로 기울였다.** 기울인 각도는 확인 못 함 [R-15] | 2차 기사 + Iwata Asks 대조 |
| 스타크래프트 1 각도 | 확인 못 함 | — |
| 각도별 화면 배율 | 30도: 높이 0.866·깊이 0.5 / 45도: 둘 다 0.707 / 60도: 높이 0.5·깊이 0.866 [R-14] | 기하 계산(추론) |
| 건물·성벽 높이(칸 대비) | 사례 수치는 확인 못 함. 45도에서 월드 높이 1.41칸 → 화면 16px, 2.12칸 → 24px, 2.83칸 → 32px [R-14] | 기하 계산(추론) |
| 가림 | 높은 물체의 윗면이 바로 뒤 칸을 «앞면 높이 ÷ 16px» 줄만큼 덮는다 [R-14] | 기하 계산(추론) |
| 성벽 위·등반·비행 유닛 표현 | 확인 못 함 | — |

## 2. 요점

### Factorio 45도 [R-13]
- 정사각 격자 + 비스듬한 시점에서 1차 출처로 각도 수치가 나온 사례는 이것 하나다.
- 3D 형체를 45도 정사영 카메라로 렌더해 16px 정사각 칸에 맞추려면 **바닥 깊이를 √2배로 모델링**한다. 렌더 뒤 이미지를 늘리지 않는다는 전제다.
- 대가 1: 개발자가 "아마 실수였다"고 적었다. 같은 길이의 화차가 세로로 놓이면 가로보다 41% 적은 칸을 차지했고, 스프라이트를 늘려 숨길 수 없었다. 이 프로젝트에서는 회전하는 대포 포신과 큰 보스가 같은 문제를 겪는다(추론).
- 대가 2: 45도는 기준값일 뿐이다. 큰 엔티티는 기하를 비틀었다(오일 정제소는 회전마다 모델 4개).
- 포럼의 38도는 측정자가 철회했고, 53도는 출처가 없다.

### 각도·높이 기하 [R-14] (추론)
- 고도각 θ의 정사영에서 세로 높이는 cosθ배, 바닥 깊이는 sinθ배로 화면에 나온다.
- 이 프로젝트의 맵은 마을·성곽이 위, 적은 아래에서 올라온다(SPEC S51). 그래서 다음과 같다.
  - 성벽이 가리는 쪽은 성벽 바로 뒤 마을 첫 줄이다. 성문 앞에 몰린 적은 가려지지 않는다.
  - 들판 타워는 그 뒤(위쪽), 곧 타워와 성벽 사이의 적을 가린다.
  - 성벽 위에 선 유닛은 앞면 높이만큼 위로 올려 그린다.
- 고도각을 올리면 가림이 줄고 입체감도 준다. 1차 조사의 The Last Spell «시점 높이기» [R-07]와 같은 방향의 대가다.

### 젤다 ALBW [R-15]
- 카메라를 바로 위에 두면 링크의 모자만 보인다. 그래서 링크·루피 같은 물체를 뒤로 기울여 얼굴과 몸이 보이게 했다.
- 이 프로젝트로 옮기면: 바닥 타일은 수직 탑다운으로, 유닛·건물은 각자 기울인 카메라로 렌더해 발밑을 칸에 맞춘다(적용 해석).
- 대가: 기울인 각도가 없다. 물체 발밑 깊이와 타일 깊이가 어긋나는 부분을 따로 처리해야 한다.
- 《신들의 트라이포스》(ALttP)는 손 도트라 3D 카메라가 없다. 같은 원리로 묶은 것은 2차 기사의 해석이다.

## 3. 확인 못 함

- 스타크래프트 1과 탑다운 RPG의 카메라 각도
- 건물·성벽을 칸 대비 얼마나 높게 그렸는지의 사례
- 성벽 위 유닛, 성벽을 기어오르는 유닛, 성벽을 넘는 비행 유닛의 표현 사례(그림자 분리·위쪽 오프셋·크기 변화)
- 방향 수를 정한 개발자 근거
- Godot 4.7에서 성벽 앞·위·뒤 유닛과 비행 유닛의 그리기 순서를 나누는 법(y_sort_enabled·z_index·TileMapLayer). 공식 문서로 확인해야 한다

이 빈 곳은 10/21 시험에서 같은 모델을 45도·60도로 나란히 렌더해 직접 판정한다(README «시험 설정값 후보»).
