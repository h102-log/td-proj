# 마을 길 배치 조사 — 중세 마을의 길을 우리 성 안 마을에 어떻게 놓나 (2026-10-26)

## 0. 결론 먼저

### 한 줄

**중세 마을의 길은 «문 → 좁은 큰길 → 넓어진 시장 → 그 너머 끝의 성» 순서이고, 성(거점)은 대개 마을 한가운데가 아니라 문 반대편 끝에 있었다.** 우리 마을은 이 순서가 뭉개져 있다. 거점이 한가운데 있고, 문에서 거점까지 폭 6.5칸 박석 띠가 한 폭으로 곧게 이어진다. 그 둘레에는 길망이 없다.

### 거점 위치 — 사용자 직감이 맞다

사용자는 조사 도중 «중앙 거점이 지금보다 더 위로 가야 마을이라고 형성할지도»라고 물었다. 역사 두 갈래와 게임·생성기 갈래가 따로 조사해 같은 답에 닿았다.
- 성곽 도시의 성은 거의 늘 가장자리·높은 곳에 성벽과 붙어 있었다(Conwy, Carcassonne, Rothenburg, Ludlow, Caernarfon, Flint). 마을은 문과 성 사이에 펼쳐졌다.
- 계획 마을에서도 영주 저택·교회는 «마을 끝의 큰 구획»이었다.
- Watabou 생성기는 가운데를 광장으로, 성채를 가장자리로 둔다. Thronefall도 성을 뒤쪽 끝에 둔다.
- 마을 가운데에 오는 것은 대개 **교회**였다(동심원 마을, 요새 교회).
- 사용자가 보여 준 조감도도 궁전이 큰길 끝에 있고 가운데는 광장이다([03](03_reference_image.md)).

조건이 둘 있다([02](02_keep_position.md)).
- 이 결론은 **문이 하나**일 때의 답이다. 나중 사방 성벽에 문을 여럿 내면 가운데가 맞다.
- 거점 자리는 **시뮬레이션 값**이다. 6행으로 올리면 적이 성 안에서 걷는 세로 거리가 13줄에서 20줄이 된다(계산). S37·S203(둘 다 사용자 결정)을 바꾼다. 코드는 `src/main.gd:191` 한 값과 좌표 두어 곳이다.

### 길 배치 규칙

자세한 표와 근거는 [01](01_medieval_grammar.md)·[04](04_layout_plans.md) 1장에 있다.

| # | 규칙 | 한 줄 근거 |
|---|---|---|
| R1 | 띠를 나눈다: 문 안 공터 → 큰길 2~3칸 → 시장 10~13칸(방추꼴) → 거점 앞 빈터 | 문 길은 좁고 시장에서 넓어진다. 6.5칸은 길이 아니라 광장 폭이다 |
| R2 | 박석은 문 안·시장·거점 앞만. 큰길은 박석–흙–박석이나 자갈, 나머지는 흙 | 포장은 1249년 이후 시장·큰길부터. 골목은 모래·자갈 |
| R3 | 길망: 시장에서 동서 가로 길(T자), 블록 5~6칸 간격 뒷길, 남북 샛길 | 큰길 하나면 진격로로 읽힌다. 길망 속 한 줄이면 마을 길이다 |
| R4 | 막다른 길 없음 | 길은 문·광장·교차로에서 끝난다 |
| R5 | 큰길은 곧게, 골목은 한두 칸 어긋나게 | «방어용 꼬불꼬불한 길»은 근거가 약하다. 12~14세기는 곧은 길을 선호했다 |
| R6 | 성벽 안쪽 길은 1칸 흙·자갈, 모서리는 텃밭·과수원 | 성벽 길은 실재했지만 둘레 전체는 드물고, 모서리는 정원이었다 |
| R7 | 갈림길에 점 표시(우물·시장 십자가·나무) | 픽셀아트 사례와 시장 십자가 |
| R8 | 들판 흙길은 문에서 박석으로 바뀐다 | 카카리코, 참고 그림의 «밖으로 이어진 길» |

길 폭 권장값(큰길 2~3칸, 골목 1칸)은 중세 실측(큰길 6~10 m, 뒷길 1~3 m)을 1칸 2.5~4 m로 옮긴 값이다. 픽셀아트 마을의 «길 폭 = 건물 폭의 0.25~0.5배»와도 맞는다.

### 세 안

칸 스케치는 [04](04_layout_plans.md) 2장에 있다.

| 안 | 내용 | 시뮬레이션 | Claude 의견 |
|---|---|---|---|
| **A 거점 위로** | 거점 (30,6). 지금 거점 근처를 시장으로. 문 → 큰길 → 시장 → 좁은 길 → 거점 | 바뀜 | **문이 하나로 남는다면 권함** |
| B 가운데 동심원 | 거점 그대로, 둘레 고리 길 두 겹 + 어긋난 방사 골목 | 그대로 | 직사각 건물과 고리가 어긋날 위험. 문이 여럿일 때만 |
| C 그대로 + 띠 나눔 | 거점 그대로, 거점 앞을 시장으로 넓히고 아래는 큰길로 좁힘, 길망 추가 | 그대로 | 시뮬레이션을 지금 건드리기 싫으면 먼저. 코드는 A로 옮기기 쉽게 |

- 건물이 길 위에 서면: 지금 흙 터(S215)가 흙길을 덮게 둔다. 박석은 터가 덮지 않으니 시장·문 안은 저절로 남는다. 큰길·시장 건설 금지는 시뮬레이션 변경이라 시안 뒤에 묻는다.
- 참고 그림의 «지붕 바다»는 길로는 못 만든다. 길이 하는 일은 몇 채만 있어도 줄 맞춰 보이게 하는 것이다. 빈 블록은 «그대로 → 비면 텃밭·과수원» 순서로 본다. 배경 집은 지을 땅을 줄이는 규칙 변경이라 11/9~30 몫이다.
- 이전 마을 조사의 F5(«정문→거점 축엔 길을 내지 말자»)와 방향이 다르다. 중세 큰길이 바로 그 축이기 때문이다. 그래서 축을 비우는 대신 좁히고, 시장에서 끊고, 길망 속 한 줄로 만든다([04](04_layout_plans.md) 5장).

### 사용자 결정 질문

선택지와 Claude 의견은 [05](05_decisions.md)에 있다.

- **Q1** 거점을 옮길까?(A 위로 / B 가운데 동심원 / C 그대로 + 띠 나눔)
- **Q2** 나중 사방 성벽에서 문은 몇 개인가?(하나 / 여럿 / 모름)
- **Q3** 박석 띠를 큰길 + 시장으로 나눌까?
- **Q4** 박석을 문 안·시장·거점 앞으로 줄일까?
- **Q5** 큰길·시장 위 건설을 막을까?(시안 뒤)
- **Q6** 빈 블록을 텃밭·과수원으로 채울까?(시안 뒤)
- **Q7** 시안은 A와 C를 나란히 찍을까?

권하는 순서는 Q1·Q2 → A·C 시안(반나절~1일) → Gemini 두 단계와 사용자 판정 → 구현이다. 구현은 바닥 골격 1~1.5일이고, A면 거점 이동 반나절~1일이 더 든다(Claude 추정).

### 사용자 결정과 시안(2026-10-26, 조사 뒤)

- 사용자 답: 처음엔 Q1 «A»였다가 «거점은 중앙이 좋음»으로 바꿨다. Q2는 «상하좌우 4개»이고, 적은 지금처럼 남쪽에서만 나온다. «추후에 적이 4방향으로 침입하게 하려고 한다»(미계획).
- 적이 네 방향에서 오면 조사의 조건부 결론도 «가운데»다([02](02_keep_position.md) 6장). 그래서 **안 D(가운데 거점 광장 + 십자 큰길 넷 + 엇갈린 고리 길)**를 만들어 찍었다([04](04_layout_plans.md) 2장 안 D).
- 시안 이미지: `art/trial/preview/village_roads/`(1 지금·D 전경, 3 게임 화면, 4 정문, 5 건물 없는 D).
- Gemini 판정은 아직이다. Chrome 확장이 연결되지 않았다.
- 이어서 사용자가 «가로 성벽길이만큼 세로 성벽도… 정사각형 틀 … 정가운데에 거점», «전체적인 맵 사이즈가 커져야함»을 요청했다(시안 먼저, 바깥 60×60, 문 넷). **안 E**(맵 60×93, 사방 성벽, 거점 (30,30), D 골격을 두 겹 고리로 넓힘)를 찍었다. 이미지는 `art/trial/preview/village_square/`에 있고 내용은 [04](04_layout_plans.md) 안 E에 있다. 집 상한 6채 그대로면 빈 블록이 D보다 훨씬 넓다.
