# 적 테마 라운드 조사 — 라운드마다 다른 적 테마(일반 적·변종·보스)를 설계할 근거 (2026-10-27)

## 0. 결론 먼저

### 한 줄

**«테마는 라운드에 붙은 적 목록, 난이도는 라운드 자리에 붙은 예산»으로 나누면 테마를 바꿔 끼워도 곡선이 지켜진다.** Into the Breach가 그렇게 짰다(섬 = 적 목록, 섹터 = 허용 종류 수·강화형 비율) [B-04][B-05]. 원작도 «한 판 = 한 군단, 군단 안은 한 축만 다른 2~5종»이다 [C-01][C-02]. 그리고 3라운드를 «고블린 약탈단»으로 두면 **테마 때문에 바뀌는 보스는 1·2라운드 둘뿐이다**(오우거 → 슬라임 킹, 미노타우로스 → 알파 늑대). 3~6라운드 보스는 기존 설계(고블린 족장·와이번·트롤 공성꾼·오크 대족장)가 그대로 테마 보스가 된다([03](03_boss.md) 6장).

### 근거로 본 다섯 가지

1. **분열·부활·소환은 «생겨난 적의 보상 0»으로 경제를 막는다.** Kingdom Rush 위키는 소환·산란된 적 여럿을 «골드를 주지 않는 예외»로 적는다. 다만 판마다 다르다(KR1 Spider Hatchling은 iOS·Flash판에서 1골드) [W-12, V2 부분 확인]. BTD6 Bloonarius가 뿌린 풍선도 보상이 없다 [W-26, V13 확인]. 물량은 «자식까지 센 체력 합»(BTD6 RBE)으로 센다 [W-08].
2. **개체 수가 우리 쪽 가장 큰 제약이다.** 살아 있는 적 260마리쯤부터 60fps 아래이고, 6라운드 마지막 웨이브는 802마리다(`next/2026-10-24/r3.md:343`, [07](07_sim_mapping.md) 1.1). 부활 선례는 «횟수 상한» 대신 **재료**(시전자·시체·무리 생존)로 수를 막았다 [A-14][A-16][W-24].
3. **빼앗는 적은 «한 번에 하나, 바로 퇴각, 되찾을 수 있음, 잃어도 판이 안 끝남»으로 다듬어졌다.** 팬 위키에 따르면 Monster Hunter의 Melynx는 «하나만 훔치고 바로 물러나게» 바뀌었다(1차 인터뷰는 못 찾음) [W-21, V5]. Defense Grid는 떨어진 코어가 천천히 떠서 돌아간다 [W-01, V4 부분 확인]. 불만은 «영원히 데려감»에 몰렸다 [W-22].
4. **예고 동안 끊을 수 있게 하면 우리 보스 공통 규칙과 같은 꼴이 된다.** Diablo IV는 늘 켜진 장판을 «6초 지속(가동률 50~75%) + 기절·빙결로 끊김»으로 고쳤다 [W-19, V9 부분 확인]. PvZ 번지 좀비는 표적 위에 머무는 동안 얼리기·마비로 끊긴다(3초는 한 출처뿐) [W-02, V1]. L4D Hunter는 웅크린 뒤 덮치고, 웅크릴 때 울음·덮칠 때 비명이 소리 예고다(1초는 한 출처뿐) [A-01, V11].
5. **수가 많을 때 사망 효과·장판은 개발사가 줄이거나 껐다.** Path of Exile 2는 0.2.0e에서 Blood Cretin 사망 웅덩이를 6초에서 4초로 줄였고, 0.2.0 Hotfix 7에서 소환수(Spectre)로 쓰는 몬스터의 사망 효과를 껐다. «예고가 흐린 사망 효과를 껐다»는 원래 요약 문구는 노트에서 찾지 못했다 [W-20, V8 판단 불가]. 우리 물량에서는 분열보다 사망 폭발·장판이 더 위험하다(추론, [04](04_failures.md) F5).

### 무작위 테마 풀 안

- **추천: 지금은 고정 순서로 만들되, 데이터는 처음부터 «테마 = 적 목록 + 보스»와 «자리 = 물량 예산·허용 종류 수·변종 비율·체력 배율(S144)»로 나눈다.** S133(판마다 웨이브를 무작위로)을 구현할 때 테마만 섞으면 된다(ITB 꼴 [B-04][B-05]).
- 섞을 때는 1·6라운드 고정, 2~5라운드만 풀에서 뽑는다(Monster Train 3·6·8 고정, ITB 마지막 섬 고정 [B-06][B-04]). 같은 테마를 잇지 않고, 쉬운 판을 키운 판을 바로 뒤에 두지 않는다(StS [B-02]).
- 보스가 테마에 묶이면 보스 순서도 섞인다. 10/22 결정(«보스는 처음 나올 때부터 스킬을 다 쓴다»)과 맞추려면 자리 쪽 손잡이는 체력 배율(S144) 하나다. 이 값은 데이터에 있다(CLAUDE.md «손잡이»).
- 물량 예산은 «자식까지 센 체력 합»(RBE식)으로 두면 분열 테마도 같은 단위에 들어간다 [W-08]. 원작도 단단한 테마일수록 수가 적다([05](05_source_work.md) 3장).

### 조사 방법 요약

```
1차  deep-research 워크플로: 검색 각도 5 → 검색 결과 30(W-01~30)
     → 출처 22개 원문 읽기 모두 실패(네트워크 정책) → 주장 추출 0 → 3표 검증 단계 못 감
보충 연구자 3명, 각 WebSearch 14번: A Q1 나머지 기믹 25(A-01~25) · B Q2·Q3 23(B-01~23) · C Q5·Q6 16(C-01~16)
검증 반박 검증 1명, WebSearch 16번: 핵심 주장 15개(V1~V15)
     → 확인 2 · 부분 확인 9 · 엇갈림 2 · 반박 0 · 판단 불가 2. 부분 확인은 고친 문장으로 본문에 반영
저장소 Q7은 메인 세션이 코드·데이터·SPEC을 직접 읽음(07). 코드는 고치지 않았고 측정은 돌리지 않았다
합계 주장 94 · 에이전트 32(워크플로 28 + 보충 3 + 검증 1)
```

- **원문을 하나도 열지 못했다.** 이 환경의 네트워크 정책이 `*.fandom.com`·`bloonswiki.com`·`*.wiki.gg`·`namu.wiki`·`en.wikipedia.org`·`web.archive.org` 등을 막는다(프록시 403, WebFetch `ENOTFOUND`). 그래서 웹 근거는 모두 **검색 결과 요약**이다. 원문 대조를 하려면 환경 설정 Network access에서 이 호스트들을 허용한 뒤 다시 돌려야 한다.
- **비공식 사본**: 보충 B는 GitHub에 올라온 게임 데이터·디컴파일 코드 사본 4건(Slay the Spire·Into the Breach·Plants vs. Zombies·Kingdom Rush 1)을 세어 수치를 냈다. 판 번호를 모르고 모드가 고쳤을 수 있다. 이 문서에는 코드 줄을 옮기지 않고 규칙만 말로 적었다. 같은 내용을 검색 요약이 받쳐 준 것(StS 풀 규칙, PvZ 새 좀비 레벨, KR1 적 30종)을 결론의 근거로 먼저 썼다.
- **줄인 것**: 우선순위 Q1 > Q4 > Q2 > Q3 > Q5 > Q6에 따라 워크플로는 Q5·Q6을 뺐고, 보충 C가 각 7번씩만 검색했다. 못 찾은 것은 각 파일 끝과 [99](99_sources.md) «못 찾은 것»에 있다. 큰 빈칸은 늑대 무리 보너스 선례, 출시 게임의 보스 예고 길이 원문 수치, 늑대 도트 방향 수 관례, Stronghold·WC3 선례다.
- 프롬프트는 에이전트를 «10개 안팎»으로 잡았다. 워크플로가 구조상 28개를 썼다(검색·원문 읽기 에이전트가 많다). 원문 읽기가 다 실패해서 3표 검증 에이전트(75개 예정)는 돌지 않았다.
