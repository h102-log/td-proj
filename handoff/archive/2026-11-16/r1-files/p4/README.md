## 추천

**초상은 안 C다.** 고른 영웅은 모두 S372 «고른 칸»(금색 테두리)이고, 스킬 쓸 영웅 하나에만 초상 오른쪽 변에 스킬 칸 쪽을 가리키는 금색 세모가 붙는다. 까닭은 넷이다.

1. 실제 크기에서 늘 같은 세기로 보인다. 세모는 스킬 칸이 잠겼든 대기 중이든 그대로다. 안 A는 글자색뿐이라(금색 대 흰색 밝기 대비 1.15, 계산) 초반(E·R 잠김)에 Q가 대기 중이면 금색 글자가 W 하나와 7px짜리 Q뿐이고, 넷이 모두 대기 중이면 7px 글자 넷뿐이다(`top_hard.png` 1·2).
2. «이 영웅만 대시한다»로 읽히지 않는다. 고른 영웅이 모두 같은 테두리라 Space·우클릭(고른 영웅 모두)과 맞고, 세모는 초상이 아니라 스킬 칸을 가리킨다. 안 B는 원정에서 셋을 드래그로 골라도 1번만 금색이고 둘은 청록이라 «1번만 골랐다»로 읽힌다(`top_hard.png` 3). 이것이 S369 ①이 말한 바로 그 장면이다.
3. 색에 기대지 않는다. 세모는 모양이라 금색이 많은 스킬 칸(오토 꺾쇠, 조준 맥박) 옆에서도 뜻이 갈린다.
4. S372에 새 상태가 생기지 않는다. 초상은 «고른 칸» 그대로이고, 더하는 것은 도트 그림 하나(4×7px)다. B의 청록 테두리는 S372에 없는 새 상태다.

안 C의 약점: 세모가 작다(창 1280×720에서 8×14px). 초상 그림 오른쪽 3px을 가린다. Q 칸이 오토(금색 꺾쇠)면 세모와 꺾쇠가 나란히 놓인다(`top_C.png`의 2번 영웅). 더 또렷해야 하면 A의 금색 글자를 겹친다(`top_bands.png`·`top_hard.png`의 «안 A + C»). 자리가 달라 부딪히지 않는다.

## 1. 초상 한 칸(24×24)

### 세 안에 똑같이 넣은 것(후기 3 안 A의 «대기 표시(최소)»)

- 남은 대시 초: 지금의 대기 막(검정 60%, I261 ⑦) 위 초상 가운데에 올림한 초를 쓴다. 글자는 10px·e8e8e8이고 검은 테를 둘렀다(테는 건설 격자 비용 글과 같은 값). 스킬 칸의 초(18px 칸에 8px)와 같은 비율이다. 표의 «대시 대기 3.2초» 열에서 «4»다.
  - 첫 시안은 8px이었다. 막이 얇을 때(남은 1초) 밝은 초상 그림(크로노스) 위에서 숫자가 묻히고, 오른쪽 아래 레벨 숫자(7px)와 크기가 비슷해 헷갈렸다. 10px으로 키웠다(`crit/probe2.png`에 둘을 나란히 뒀다).
  - 왼쪽 위 키 «1», 오른쪽 아래 레벨과 겹치지 않는다. 왼쪽 아래 장비 아이콘(8×8)과는 숫자 테의 모서리가 1px쯤 닿을 수 있다 [추론](장비를 낀 영웅은 찍지 않았다).
- 대기 중 Space: 초상 테두리가 0.3초 빨갛다(ef3a0c, 스킬 칸 거부 I151과 같은 색·길이). 토스트 «대시 대기 N초»와 `refuse` 소리를 낸다. 여럿 골랐으면 «아무도 대시하지 못했고 대기 중인 영웅이 있을 때»만 낸다(후기 3의 Claude 기본값). 번쩍이는 것은 대기 중인 영웅의 초상이고, 토스트의 N은 그 가운데 가장 짧은 대기다.
- 쓰러진 영웅: 지금처럼 회색 초상뿐이다. 고른 채 쓰러져도 테두리·숫자·스킬 영웅 표시는 없다.
- 발밑에는 아무것도 더하지 않았다(기본값 «초상에만»).

### 안마다 다른 것: «고름»과 «스킬 쓸 영웅»

| | 고른 영웅(S369 ①) | 스킬 쓸 영웅(후기 2 안 A) | «이 영웅만 대시»와 가르는 방법 |
|---|---|---|---|
| A · 자리 | 초상 = S372 «고른 칸»: 금색 테두리 ffd37f + 바탕 2f3440 | 그 영웅의 스킬 칸 글자 Q·W·E·R이 금색(다른 영웅은 흰색 그대로). 초상에는 더하지 않는다 | 표시가 Q·W·E·R이 사는 스킬 칸에만 있다 |
| B · 색 | 초상 테두리가 청록 3c9f9c(발밑 팀 색), 바탕은 그대로 | 초상 = S372 «고른 칸». 후기 문서의 «기본»이 이것이다 | 청록 = 같이 움직이는 몸, 금색 = 키. 둘 다 초상 위라 가장 약하게 갈린다 |

- 스킬 영웅 표시는 «고른 것 가운데 첫 산 출전 영웅»에 뜬다. 한 명만 골랐으면 그 영웅에 뜬다. 고른 영웅이 없으면 뜨지 않는다(그때는 첫 영웅이 쓴다, S119 — 물을 것 5).
- 초상 버튼은 키보드 포커스를 받지 않는다(`FOCUS_NONE`). 그래서 S372의 포커스 고리(안쪽 금색 한 겹)는 초상에 뜨지 않고, 세 안 모두 그 모양은 쓰지 않았다.

### 실제 크기에서 따진 것

밝기 대비는 계산값이다(WCAG 식). 판단은 `top_bands.png`·`top_hard.png`의 실제 크기 그림으로 했다.

| 가를 것 | A | B | C |
|---|---|---|---|
| 안 고름 ↔ 고름 | 금색 대 평소 테두리 697288 = 3.41. 또렷하다 | 청록 대 697288 = 1.52. 보이지만 약하다 | A와 같다 |
| 고름 ↔ 고름 + 스킬 영웅 | 글자색 1.15. 스킬 칸이 모두 쓸 수 있을 때만 눈에 띈다 | 청록 대 금색 2.24. 또렷하다 | 세모가 있고 없고. 스킬 칸 상태와 상관없이 같다 |
| 스킬 영웅 ↔ S372 «고른 칸» | 초상의 «고른 칸»은 «고름»이다. S372의 뜻 그대로다 | 초상의 «고른 칸»이 «스킬 영웅»이고 «고름»은 청록이다. S372의 말(고른 칸 = 고른 것)과 어긋난다 | A와 같다 |
| 스킬 영웅 → «이 영웅만 대시»로 읽히나 | 읽히지 않는다(초상에는 표시가 없다) | 읽힐 위험이 가장 크다(금색 초상 하나, 나머지는 다른 색) | 낮다(초상 테두리는 모두 같고 세모는 스킬 칸을 가리킨다) |

### 따진 것

- 0.7초 안에 차이가 보이나: 2배 줌에서는 잔상 넷과 먼지가 또렷하다. 1배 줌(원정)에서는 실루엣이 크림색 띠로 보인다. 반투명 영웅 그림은 1배 줌의 어두운 바닥에서 흐린 회색 그림자로만 보인다(`dash_ghost_1x.gif`).
- 도트 그림 결: 잔상·먼지 자리는 맵 px에 맞고 Nearest로 그린다. 실루엣과 먼지는 팔레트 색(`PX`의 cream·tan·ash, DUST)만 쓴다. 불투명도를 쓰는 것은 기존 효과(먼지 점, 흔적)와 같다. 먼지의 크림 → DUST는 기존 `_dot`처럼 두 색 사이를 이어서 섞는다.
- 0.5칸 이하 대시: 미끄러짐이 없어 몸은 그대로 툭 옮겨진다. 시안은 몸 뒤에 실루엣 한 겹(몸에 거의 가려 가장자리만 보인다)과 먼지 조금, 0.1초 걷기 자세를 더한다. «이어 준다»기보다 «대시가 먹혔다»를 알리는 정도다(`dash_compare_2x_short.gif`).

### GIF 읽는 법

- 60분의 1초 스텝으로 대시 앞 0.2초 ~ 뒤 0.5초 42장을 찍었다. 실제 속도 GIF는 두 장에 한 장을 골라 30fps로 돌린다(GIF는 60fps를 제대로 못 돌린다). 그래서 미끄러짐 0.12초가 GIF에서는 네 장쯤이다. 게임(60fps)에서는 일곱 장이다. 끝 프레임은 0.6초 붙든다.
- 자르기 440×260 창 px을 Nearest 2배로 키웠다(잔상 모양 비교는 300×260). 두 줌이 같은 크기라 원정(1배)에서 영웅이 절반으로 보이는 것이 실제 비율이다.
- 2x(수성): 정문 앞에서 이그니스 하나가 동쪽으로 2칸. 대상이 없다.
- 1x(원정 1층): 왕의 첫 도약 예고가 뜨면 셋이 원(반경 2.5칸) 안 동쪽 가장자리로 단체 이동하고, 착지 0.4초 전에 셋이 함께 동쪽으로 대시한다. 지금 쪽에서는 왕을 노리던 실비아가 왕 쪽을 본 채 동쪽으로 미끄러진다. 시안 쪽은 셋 다 대시 쪽을 본다.
- `_late`: 같은 장면에서 착지 0.1초 전에 대시했다. 잔상이 원 안에 남은 채 왕이 내려앉는다. 영웅은 맞지 않는다(체력 그대로). 실루엣은 색이 한 가지라 원 안에 남아도 몸으로 보이지 않는다.
- `_short`: 0.25칸(4px) 대시.

## 3. 이번 비평에서 고친 것과 남긴 것

## 5. 물을 것

1. 초상 안: A / B / **C(추천)**. C에 A의 금색 글자를 겹칠 수도 있다(기본값: 겹치지 않는다).
2. 잔상 모양: **1 단색 영웅 실루엣(시안 기본)** / 2 반투명 영웅 그림 / 3 단색 막대.
3. 대시 소리: **`swing`(추천)** / `arrow` / 없음.
4. «부드럽게 이어진다는 느낌이 안듬»의 뜻: **(가) 순간 이동처럼 끊겨 보인다(시안이 이렇게 읽었다)** / (나) 튀어 나가는 맛이 없다 / (다) 대시 뒤 하던 이동이 끊긴다. (나)·(다)면 다른 시안이 필요하다.
5. 고른 영웅이 없을 때(첫 영웅이 쓴다, S119)도 스킬 영웅 표시를 첫 영웅에 둘까: **두지 않는다(시안)** / 둔다. A·C는 둘 수 있고 B는 둘 수 없다.
6. 대기 표시를 발밑에도 둘까: **초상에만(기본값)** / 발밑에도(S315의 «초상에» 절이 바뀐다).

## 6. 찍은 방법과 확인한 것

- 실시간을 쓰지 않았다. `main`·HUD·카메라의 `_process`를 끄고 스크립트가 직접 돌렸다. 대시와 대기 중 Space는 사람과 같은 길(`push_input` → main → controls)로 넣었다.
- 판: 씨앗 7(영입 목록 고정)로 영웅 셋(실비아·이그니스·크로노스)을 영입하고 병사 넷을 놓은 1라운드 전투 단계. 표와 GIF는 최대 레벨이고, `top_hard.png`의 ①만 레벨 2다. 원정은 2라운드 준비 단계에서 들어간 1층이다.
- «지금» 줄과 «지금» GIF는 HEAD 사본(`git archive HEAD`, `work/head_tree`)에서 찍었다.
- 시안 트리에서 시안을 끈 화면은 HEAD 사본과 픽셀이 같다: 초상 상태 여섯 장, 수성 대시 42장 모두 차이 0.
- 시안 트리(시안 끔)에서 돌린 것: `pytest tests/eval/test_hud.py tests/eval/test_heroes.py` 103 통과·34 건너뜀(건너뛴 34는 모두 «머지 전용(C)» 화면 평가다), EV890·EV1105·EV573 통과, 유닛 `test_fx.gd` ALL PASS. 전체 pytest와 eval-run은 돌리지 않았다(머지하지 않는 시안).
- 표·띠 그림과 GIF에서 뽑은 프레임을 직접 열어 확인했다(`crit/`).
- 난이도·밸런스 측정은 하지 않았다.

다시 찍기(셸 한 줄씩):

```bash
export XDG_DATA_HOME=<스크래치패드>/xdg/p4
cd <스크래치패드>/wt/p4
timeout 200 xvfb-run -a -s "-screen 0 1920x1080x24" godot --path . -s <이 폴더>/cap_portrait.gd -- <이 폴더>/work/portrait

```

## 7. 한계

- 캡처는 xvfb의 소프트웨어 OpenGL이다. 사용자 PC의 그림과 px이 같을 것으로 보지만 견주어 보지는 않았다 [추론].
- «실제 크기»는 창 1280×720(기준 해상도의 2배)이다. 더 큰 창·전체화면에서는 같은 그림이 정수배로 커진다.
- 원정 GIF의 영웅 셋은 단체 이동으로 한 자리에 겹쳐 서 있어 잔상도 한 덩어리로 보인다.
- 마우스 올림 상태, 준비 단계의 모습, 장비를 낀 영웅, 영웅이 한둘뿐인 판은 찍지 않았다.
- 소리는 듣지 못했다.
