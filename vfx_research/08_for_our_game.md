# 08. 우리 게임에 옮기기 — 진단, 원칙, 스킬 유형별 아이디어, 결정 질문

이 문서는 **제안**이다. SPEC·코드는 바꾸지 않았다. 근거는 01~07에 있고, 여기서는 «(근거 문서 §)»로만 가리킨다.

## 1. 진단: 왜 «그림판에 그린 듯» 보이나

중요한 순서다.

1. **해상도가 섞였다(mixel).** 10/25부터 맵을 창 해상도로 그려서, 도트 그림 옆에 `draw_arc` 원은 화면 픽셀로 매끈하게, 굵기를 주지 않은 무늬 선은 화면 1px 머리카락으로 그려진다. 실행 화면으로 확인했다([06 §1](06_godot_tech.md), [그림](img/now_ignis_e_crop3x.png)). 장판 무늬는 S168의 «맵 1px»와도 어긋난다.
2. **움직임이 한 단계뿐이다.** 모든 흔적이 «굵기 고정 고리가 커지며 알파가 준다» 하나다. 다른 게임은 섬광 → 터짐 → 흩어짐으로 단계를 나누고, 굵기를 1 → 0으로 줄이며, 짧은 충격과 긴 잔해를 겹친다([02 §1·§8](02_pixel_craft.md), [03 §1](03_code_drawn_games.md)).
3. **색이 한 색이고 팔레트 밖이다.** 이펙트마다 한 색에 알파뿐이다. 상태 고리는 순수 RGB다. 다른 게임은 이펙트마다 3~6색 램프(흰 심 → 본색 → 어두운 색)를 쓰고, 사라질 때 알파 대신 어두운 색으로 간다([02 §1·§3](02_pixel_craft.md), [04 §3](04_sprite_games.md)).
4. **위계가 없다.** 상태 12종이 모두 같은 1px 고리이고, 장판은 판정 경계(테두리)가 안쪽 무늬보다 약하다([01 §5](01_principles.md)).
5. **무늬가 재질이 아니라 기호다.** 다른 게임의 장판은 덩어리·방울·조각·타일 질감이다. 반투명은 «성글게» 또는 «알파 몇 단계»로 낸다([04 §3](04_sprite_games.md), [05 §2](05_status_and_zones.md)).

잘 되고 있는 것: 피격 흰 실루엣 번쩍임, 보스 예고의 구조(차오름 → 발동 채움), 효과 점 `_fx_dots`(아트 px 사각형, 시드 해시)는 다른 게임과 같은 방식이다. 지금 구조를 버릴 필요는 없다.

## 2. 우리 판 원칙 (제안)

| # | 원칙 | 근거 |
|---|---|---|
| P1 | **모든 이펙트를 아트 px 격자로 그린다.** 원·선은 아트 px `draw_rect`(미리 구운 원 모양)나 아틀라스 텍스처로 그린다. 화면 px 선은 쓰지 않는다. 위치는 지금처럼 반올림하지 않아도 된다(S165) | 06 §1·§2 |
| P2 | **단계를 나눈다.** 섬광 1~2프레임 → 터짐 2~4프레임 → 흩어짐 3~4프레임. 범위 고리는 앞 25%만 굵게(아트 3 → 0px) 보이고, 무게는 연기·파편으로 준다 | 02 §1, 03 §1 |
| P3 | **이펙트마다 3~4색 램프.** 흰 심 → 본색 → 진한 색 → (연기) 회색. 사라질 때는 어두운 색으로. 반투명은 성기게(30~55%) 또는 계단 알파 2~3단 | 02 §1·§3, 04 §3 |
| P4 | **겹을 쌓는다.** 범위(고리) + 무게(연기·파편) + 속도(불티 방사선). 무작위는 사건 번호 해시 `_h`로 | 03 §1 |
| P5 | **위계.** 1차 = 판정 경계·CC·보스 예고(불투명·고대비·밑칠). 2차 = 재질·장식(옅고 작게). 보스 예고가 가장 강하다 | 01 §1·§2 |
| P6 | **상태는 고리로 쌓지 않는다.** 상태마다 수단 하나(재질 오버레이·파티클·틴트·아이콘)를 배정한다 | 05 §1 |
| P7 | **모양은 효과의 종류, 색은 누구의 무엇.** 같은 모양을 색만 바꿔 다시 쓴다 | 04 §3 |
| P8 | **1px 선은 부가 정보에만.** 주된 것은 굵게 채우고 흰 심을 넣는다 | 04 §3 |

## 4. 방향 세 안 (이번 조사로 고친 판)

처음 말씀드린 A·B·C를 조사 결과에 맞춰 다시 적는다.

| 안 | 내용 | 다른 게임 | 비용(추론) |
|---|---|---|---|
| **A. 코드 그대로, 기법만** | P1(아트 px 원·선 도우미) + P2~P5를 지금 `_draw`에 넣는다. 그림 파일은 늘지 않는다 | Mindustry | 작음~중간. 도우미 하나와 흔적·장판·상태 그리기 함수들 다시 쓰기 |
| **C. 코드 + 작은 스프라이트 (추천)** | A에 더해, 결이 있는 것만 7~16px 아틀라스 조각으로 그린다(불꽃·증기·균열·번개 결·빛 띠·상태 아이콘·재질 오버레이). 움직임·색 램프는 코드로 준다 | SPD, SC 오버레이 | 중간. `tools/art/fx.py` 하나와 아틀라스 한 줄 |
| B. 전부 스프라이트 | 스킬마다 프레임 애니메이션을 그린다 | SC 마법, FFT | 큼(스킬 24 + 장판 11 + 보스) |

- C를 추천하는 이유
  - 두 조사 갈래(코드 게임·스프라이트 게임)가 같은 답을 냈다. 순간 이펙트는 코드로, 결이 있는 재질은 작은 그림으로 그린다.
  - P1 때문에 원·선을 어차피 다시 써야 한다. 그때 재질 조각을 같이 넣는 것이 두 번 손대는 것보다 싸다.
  - 아틀라스 조각과 `draw_rect`는 배치가 묶여서, 장판이 깔린 장면의 draw call(131~167)도 줄어든다(추론, [06 §2](06_godot_tech.md)).
- 무료 CC0 팩은 그대로 쓰기보다 형태·타이밍 참고용이다([07 §3](07_free_assets.md)).

## 6. 다음 단계 제안

1. **시안**: 이그니스 한 명(화염구·서리 고리·블랙홀·운석, 장판 셋)과 상태 셋(기절·둔화·초당 피해)을 «지금 / A / C»로 나란히 그린다. 정지 그림과 4배 느린 영상으로 만든다. 지금까지 시안을 만들던 방식과 같다(예: `art/trial/preview/skill_fx_a.png`).
   - → 2026-10-27에 만들었다: [`art/trial/preview/hero_fx_ignis_options.png`](../art/trial/preview/hero_fx_ignis_options.png). 명세·본 것·비용은 [`insights/2026-10-27_hero_fx_mockup.md`](../insights/2026-10-27_hero_fx_mockup.md)에 있다.
2. 사용자가 고르면 SPEC(S168·S179·I101 변경)과 평가를 먼저 고치고 구현한다.
3. 프레임 수·램프 색·크기 배율처럼 보기 좋음을 좌우하는 수치는 상수 한 곳에 손잡이로 둔다.
