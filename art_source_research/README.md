# 아트 출처 후보 조사 (WBS 1.4)

2D 도트 다크 판타지 디펜스 게임(Godot 4.7.2, Windows, 스팀 출시)의 아트를 어디서 마련할지 정하기 위한 후보 조사다. Claude가 코드로 아트를 만드는 안을 1안으로 보고, 에셋팩을 대안·보완으로 비교했다. 다른 이미지 생성 AI는 범위 밖이다. 확인 날짜는 모두 2026-10-11이다. **최종 결정은 사용자가 10/18([WBS.md](../WBS.md) 2.14)에 한다.**

## 결론

**권장안은 에셋팩 A — Minifantasy(Krishna Palacio) Complete Bundle($69.99) [A-01]을 쓰고, 게임에 실리는 아트는 팩만, Claude는 코드에만 쓰는 구성이다.** 한 작가 화풍으로 출시 범위 대부분을 채우고 [X-14] (보충 조사, 별도 검증 없음), 건물마다 건설 중·파손을 포함한 7상태가 있다 [X-04] (보충 조사, 별도 검증 없음). Claude가 가장 약한 인간형 유닛을 팩이 맡는다 [Q-22]. 스팀 AI 공개가 필요 없을 가능성이 높고 [P-05], WBS R1·2.14와도 맞는다. 대가는 8px 타일에 맞춘 해상도 재결정 [A-10]과 확인 불가 항목(시트 프레임 수, 타워 공격·투사체, 성벽 파손) [X-02] [X-07] [X-08] (보충 조사, 별도 검증 없음)이다. **예비안은 Ninja Adventure(CC0, 16px) [A-12] + Claude 보충(다크 팔레트 변환, 시설 제작) 하이브리드다.** Minifantasy 한 팩을 사서 확인한 결과가 나쁘거나 해상도 전환을 받아들일 수 없을 때 쓴다. 사용자 1안인 Claude 단독은 권장하지 않는다. 인간형 유닛 품질이 약하고 [Q-22], 제작 시간이 중앙값 35~40시간으로 추정돼 같은 주의 제품 기능 작업과 함께 담기 어렵고 [Q-25], AI 공개가 필요하기 때문이다 [P-05]. 10/18 전 반나절 시험을 모두 통과하고 사용자가 공개를 받아들일 때만 다시 검토한다.

## 표기와 신뢰도

- 본문의 사실 문장에는 `[T-03]`처럼 주장 ID를 붙였다. ID → 출처 URL 대응은 [99 §2](99_sources.md#2-주장-대장-id--출처)에 있다.
- ID가 없는 해석은 문장 끝에 "(추론)"을 붙였다. ID가 붙은 주장 중에도 연구자가 추론으로 분류한 것이 있다. 99의 '종류' 칸에서 확인한다.
- 정책·약관·가격 문장에는 출처 URL과 확인 날짜를 본문에도 적었다.
- 프로젝트 문서([WBS.md](../WBS.md), [SPEC.md](../SPEC.md), 테스트 코드)에서 가져온 사실은 ID 대신 파일 이름을 적었다.

| 접두 | 영역 | 개수 | 검증 | 본문 표시 |
|---|---|---|---|---|
| `T-` | 기법·도구 체인 | 29 | 검증 단계 대상 아님. 핵심 주장 T-08·T-26은 미검증 | T-08·T-26에 "(1차 출처 미확인)" |
| `Q-` | 품질 사례·비용 | 28 | 핵심 9개 검증: 확인 7 · 정정 2 | 정정된 Q-07·Q-08은 정정 문장으로 씀 |
| `P-` | 정책·권리 | 25 | 핵심 15개 검증: 확인 14 · 정정 1 | 정정된 P-24는 정정 문장으로 씀 |
| `A-` | 에셋팩·폰트·캡슐 | 40 | 핵심 25개 검증: 확인 24 · 정정 1 | 정정된 A-01은 정정 문장으로 씀 |
| `X-` | 보충 조사 | 24 | 별도 검증 없음 | "(보충 조사, 별도 검증 없음)" |

- 검증에서 기각된 주장은 없다. 정정 내용과 사유는 [99 §3](99_sources.md#3-기각정정된-주장)에 있다.
- 보충 조사가 원래 주장과 다를 때(예: P-19의 arXiv 반론 부분)는 원래 주장을 본문에 쓰지 않았다. 목록은 99 §3.3에 있다.
- 출처 성격은 공식 / 1차 / 2차 / 블로그 / 포럼으로 나눴다. 사례 근거(02)는 블로그·포럼 비중이 크다.

## 조사 방법

```
1차   연구자 4명: T 기법 · Q 품질·비용 · P 정책·권리 · A 에셋팩·폰트·캡슐 → 주장 122개
검증  핵심 주장 49개 원문 대조 → 확인 45 · 정정 4 · 기각 0
공백  4주제 점검 → 결정이 뒤집힐 수 있는 2주제만 보충 조사 1회(X-, 24개)
      (Minifantasy 실제 규격 / AI 공개의 판매 영향과 Valve 입장)
      사용량 실측과 루프 정량 효과는 반나절 시험으로 대신함
```

## 사용자 확인이 필요한 곳

WBS·SPEC은 고치지 않았다. 자세한 표는 [07 §5](07_decision.md#5-wbsspec과-충돌하는-곳-wbsspec은-고치지-않았다)에 있다.

- WBS R1("직접 그리는 아트는 이 일정에 넣지 않는다")·2.14("에셋팩 선택")는 Claude 제작안과 충돌한다. 권장안(에셋팩)과는 맞는다.
- WBS 4장은 11/02~11/08에 아트 적용(4.1)과 제품 기능(4.2)을 함께 둔다. Claude 단독 추정 시간과 충돌한다.
- ~~W1(10/12~10/18)에 반나절 시험 칸이 없다.~~ 2026-10-12 해결: 10/18에 잠정 결정, 시험은 10/24~25(WBS 2.14).
- Minifantasy(8px)를 고르면 SPEC U8의 번복 조건에 해당하고, 평가 테스트의 `CELL_PX := 16`(`tests/eval/gd/lib.gd:22`)도 함께 봐야 한다.

## 알려진 한계

- Minifantasy 시트의 실제 프레임 수, 타워 공격·투사체, 성벽 파손은 판매 페이지로 확인할 수 없었다. 한 팩을 사서 봐야 한다.
- Claude 아트 작업의 사용량과 구독 한도 대비 비율은 공식 수치가 없다. 시간·사용량 추정은 가정 기반이다.
- 코드로 생성한 아트의 Steam 공개 의무를 Valve가 직접 밝힌 자료는 없다. 04의 결론은 해석이다.
- LLM 코드 아트로 출시한 게임과 픽셀아티스트의 직접 평가를 찾지 못했다.
- 전체 목록은 [99 §4](99_sources.md#4-미해결-질문)에 있다.
