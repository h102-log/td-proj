# 03. 비용과 일정 — 시간·사용량 추정과 한 주 완료 판단

질문 3에 답한다. 출시 범위 아트를 Claude로 만드는 데 드는 시간과 Claude 사용량은 얼마인가. 11/02~11/08 한 주(약 38시간) 안에 끝낼 수 있는가.

확인 날짜는 모두 2026-10-11이다. 표기법은 [README](README.md#표기와-신뢰도)에 있다.

## 요약

- 출시 범위는 한 방향 기준 약 230~260장이다. 유닛을 3방향으로 만들면 약 500장이다 [Q-24].
- Claude 단독 제작 시간은 약 20~60시간, 중앙값 35~40시간으로 추정한다 [Q-25]. 반복 횟수와 반복 1회 시간은 실측 근거가 없는 가정이다.
- 구독 한도 대비 비율은 계산할 수 없다. Anthropic이 할당량을 공개하지 않는다 [Q-02]. 반나절 시험에서 실측해야 한다.
- 한 주 완료는 조건부로만 가능하다 [Q-27]. 그런데 WBS의 같은 주에는 제품 기능(4.2)도 들어 있다. Claude 단독의 중앙값 추정만으로 그 주 38시간이 거의 다 찬다(추론).

## 1. 자산 수 세기

가정 [Q-24]:

- 16px 격자. 유닛은 16×16(보스만 32×32), 한 방향 + 좌우 반전.
- 유닛 동작은 이동 4, 공격 4, 사망 4프레임. 공병만 건설 4프레임을 더한다.
- 시설은 32×32, 정상·건설 중·파손 3상태. 타워는 공격 2프레임.
- 폰트는 기존 폰트를 쓴다(생성하지 않음).

| 자산군 | 세는 방법 | 수량 |
|---|---|---|
| 유닛 9종 (영웅 1, 용병 2, 공병 1, 적 5) | 9종 × 12프레임 + 공병 건설 4 | 약 112프레임 |
| 시설 6종 (거점, 타워 3, 성벽, 생산 시설) | 6종 × 3상태 + 타워 3종 × 공격 2 | 약 24장 |
| 들판 타일 | 기본 변형 + 오토타일 + 장식 | 28~48장 |
| 투사체·피격 이펙트 | — | 약 34프레임 |
| UI | 패널, 버튼, 아이콘 약 20, 체력바 | 약 36개 |
| **합계 (한 방향)** | | **약 230~260장** [Q-24] |
| 합계 (유닛 3방향: 아래·위·옆) | | 약 500장 [Q-24] |
| 스토어 캡슐 세트 (별도) | — | 5~8장 |

## 2. 시간 추정

가정 [Q-25]:

- '반복 1회' = 생성 코드 수정 → 확대 접촉 시트 렌더 → Claude 검수 → 사람이 훑어보기. 4~8분.
- 반복 1회의 요청 수 3~5회. 모델은 Opus 5.5, effort는 기본(max는 쓰지 않음 [Q-10]).

| 자산군 | 수량 | 반복 횟수 | 시간 |
|---|---|---|---|
| 파이프라인 준비(팔레트, 생성기 틀, 접촉 시트, 자동 검사) | — | 10~20 | 1~3h |
| 유닛 9종 | 약 112프레임 | 90~180 (종당 10~20) | 6~24h |
| 시설 6종 × 3상태 (+타워 공격) | 약 24장 | 24~48 | 1.6~6.4h |
| 들판 타일 | 28~48장 | 10~25 | 0.7~3.3h |
| 투사체·피격 이펙트 | 약 34프레임 | 8~16 | 0.5~2h |
| UI | 약 36개 | 15~30 | 1~4h |
| 캡슐 이미지 세트 | 5~8장 | 8~16 | 0.5~2h 이상 (품질 위험 큼) |
| Godot 적용(import, SpriteFrames, 9-slice) | — | — | 4~8h |
| 재작업 여유(10~20%) | — | — | 2~8h |
| **합계 (한 방향)** | **약 230~260장** | **165~335** | **약 20~60h, 중앙값 35~40h** [Q-25] |
| 합계 (유닛 3방향) | 약 500장 | +100~250 | 약 40~90h [Q-25] |

- 이 표의 반복 횟수와 반복 1회 시간은 사례 기반 가정이다. 실측 근거는 없다 [Q-25].
- 반나절 시험에서 반복 1회의 실제 시간을 재서 4~8분 가정을 고친다([08](08_half_day_trial.md)).

## 3. Claude 사용량

### 공식 문서로 확인한 사실 (확인 2026-10-11)

- Pro와 Max에는 5시간 세션 한도와 주간 한도가 있다. Claude와 Claude Code가 이 한도를 함께 쓴다 [Q-01]. 출처: https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan
  - Max에는 Fable 전용 주간 한도가 따로 있다 [Q-01].
- 플랜별 메시지 수나 토큰 할당량은 공개하지 않는다. 사용량은 대화 길이·복잡도, 기능, 모델, effort에 따라 달라진다 [Q-02]. 출처: https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work
- 가격과 배수 [Q-03]. 출처: https://claude.com/pricing , https://support.claude.com/en/articles/11049741-what-is-the-max-plan
  - Pro 월 $20(연간 결제 시 월 $17). 5시간 세션당 사용량이 Free의 최소 5배.
  - Max 5x 월 $100, Max 20x 월 $200. 각각 Pro 세션 한도의 5배·20배.
  - Max 주간 한도는 모든 모델에 걸쳐 적용되고, 계정마다 정해진 시각에 매주 초기화된다.
  - Max 가격은 웹 구독 기준이다. 모바일 가격은 다를 수 있다 [Q-03].
- 2026-05-06에 Claude Code 5시간 한도가 두 배가 됐다. Pro·Max의 피크 시간대 축소도 없어졌다. 주간 한도 변경은 언급되지 않았다 [Q-04]. 출처: https://www.anthropic.com/news/higher-limits-spacex
- 한도에 닿으면: 초기화까지 기다리기, 업그레이드, 사용 크레딧(종량제), Console API 크레딧 구매 [Q-05]. 출처: https://code.claude.com/docs/en/costs
  - Max에 딸린 월간 API 크레딧은 Claude Code에서 쓸 수 없다 [Q-05].
  - 구독의 프롬프트 캐시 수명은 1시간이다. 사용 크레딧으로 넘어가면 5분으로 준다 [Q-05].
- Claude Code 비용 문서 [Q-09]. 출처: https://code.claude.com/docs/en/costs
  - 엔터프라이즈 평균은 활동일 하루 약 $13, 90%는 하루 $30 미만.
  - Opus 5.5·Sonnet 5.5·Haiku 5.5는 extended thinking을 끌 수 없다. thinking 토큰은 출력 토큰으로 과금된다.
  - 세션이 길어지면 요청마다 전체 대화가 캐시 읽기로 다시 들어간다.
- API 가격(100만 토큰당, 캐시는 5분 TTL 기준) [Q-08]. 출처: https://claude.com/pricing
  - Opus 5.5: 입력 $4, 출력 $20, 캐시 읽기 $0.20, 캐시 쓰기 $5.
  - Sonnet 5.5: 입력 $2, 출력 $10, 캐시 읽기 $0.10, 캐시 쓰기 $2.50.
- 이미지 토큰 = ⌈가로/28⌉×⌈세로/28⌉. 16px를 16배 키운 256×256은 100토큰, 1024×768 접촉 시트는 1036토큰이다 [Q-06]. 출처: https://platform.claude.com/docs/en/build-with-claude/vision

### 추정

- 반복 165~335회를 API로 환산하면 캐시 읽기 2천만~2억 토큰, 출력(thinking 포함) 100만~1,700만 토큰이다 [Q-26].
- Opus 5.5 정가로 약 $30~450, 중앙값 대략 $100~200이다 [Q-26]. 이 추정에 쓴 캐시 읽기 단가 약 $0.2는 공식 가격 $0.20과 같다 [Q-08].
- 공식 수치 "활동일 하루 $13~30"에 7일을 곱한 $90~210과 비슷한 규모다 [Q-26].
- 비용 대부분은 thinking과 긴 컨텍스트 재읽기다. 이미지 토큰은 2% 미만이다 [Q-26].
- 구독 한도의 몇 %인지는 공식 수치가 없어 환산할 수 없다 [Q-26].
- Pro로 Opus를 써서 38시간을 집중 작업하면 5시간 한도에 여러 번 걸릴 가능성이 높다. Max가 현실적이다(추론, 신뢰도 낮음).
- WBS 위험 R6(Claude 사용량 한도)와 겹친다. 같은 주에 4.2 제품 기능 구현도 같은 한도를 쓴다([WBS.md](../WBS.md) R6·4.2).

## 4. 한 주(11/02~11/08) 안에 끝낼 수 있는가

### WBS가 그 주에 넣은 일

[WBS.md](../WBS.md) 4장은 11/02~11/08에 두 작업을 둔다.

- 4.1 유닛·타일·UI에 실제 도트 아트 적용
- 4.2 메인 메뉴, 스테이지 선택, ESC 일시정지 메뉴, 설정, 진행 저장

즉 38시간 전부를 아트에 쓸 수 없다.

### Claude 단독

- 조건부로만 가능하다 [Q-27]. 다섯 조건을 모두 갖춰야 하한~중앙값(약 30~38시간) 시나리오에 들어온다.
  1. 유닛은 16px 한 방향 + 좌우 반전
  2. 팔레트·생성기 틀·접촉 시트·자동 검사 파이프라인을 11/02 전에 완성
  3. 캡슐 이미지와 폰트는 그 주 밖에서 처리
  4. 이펙트 일부는 Godot 파티클로 대체
  5. 그 주에 코딩 작업과 사용량 한도를 나눠 쓰지 않음
- 하나라도 빠지면(3~4방향, 32px 캐릭터, 캡슐 포함) 38시간을 넘을 가능성이 높다 [Q-27].
- 조건 5는 같은 주의 4.2와 충돌한다. 중앙값 35~40시간이면 4.2에 남는 시간이 거의 없다(추론).
- 중간 점검: 11/04까지 유닛 절반을 못 끝내면 유닛은 에셋팩으로 바꾸는 하이브리드로 전환한다 [Q-27].

### 에셋팩 또는 하이브리드

- 그리는 시간이 거의 없고 적용 작업이 중심이다. Claude 단독 표의 "Godot 적용 4~8h"가 기준선이다 [Q-25].
- 추가 작업(추론):
  - Minifantasy는 8px 타일이라 해상도·격자 전환 작업이 붙는다 [A-10]. 시간은 추정하지 않았다.
  - 하이브리드는 Claude가 채울 빈 곳(타워 공격·투사체, 성벽·타워 파손 상태 등)의 제작 시간이 더해진다 [X-14] (보충 조사, 별도 검증 없음). 시설 제작은 위 표의 시설 행(1.6~6.4h)이 참고가 된다.
- 판단(추론): 에셋팩 안은 한 주 안에 끝날 가능성이 높고, 4.2에 시간을 남긴다. 하이브리드는 Claude 몫이 작을수록 에셋팩 안에 가깝다.

### 결론 (추론)

| 안 | 한 주 안 완료 | 4.2와 함께 |
|---|---|---|
| Claude 단독 | 조건부 [Q-27] | 어렵다 |
| 하이브리드 | 가능성 높음 | Claude 몫 크기에 달림 |
| 에셋팩 | 가능성 높음 | 가능 |

## 5. 10/18 시험에서 함께 잴 것

자세한 절차와 기준은 [08](08_half_day_trial.md)에 있다.

- 시험 전후로 Settings > Usage의 5시간·주간 막대와 `/usage` 수치를 기록한다 [Q-28].
- 시험(영웅 걷기 4프레임 + 타일 1세트, 반복 15~30회)은 전체의 약 1/10이다. 시험이 주간 한도의 8~10%를 넘게 쓰면 전체 작업이 주간 한도 하나에 들어가지 않는다고 본다 [Q-28].
- 1시간 작업에 5시간 세션 막대의 20%를 넘게 쓰면, 하루 5시간 이상 작업할 때 중간에 멈추게 된다고 본다(추론).
- 반복 1회의 실제 시간을 재서 §2 표를 고친다.
