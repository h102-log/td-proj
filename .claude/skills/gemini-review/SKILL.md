# Gemini 검토 (Claude in Chrome)

2026-10-18~20 일곱 세션에서 확인한 방법이다.

## 묻지 않고 진행하는 것

- **Gemini 화면의 동의 창은 묻지 않고 [동의]를 누른다.** 첫 동영상을 보낼 때 뜨는 «동영상 제작에 관한 알림»([취소]/[동의])이 그런 창이다. 사용자 원문(2026-10-20): «어차피 gemini 한테 질문하려면 허가할수 밖에없으니 무조건 수락». 창이 떠 있는 동안에는 메시지가 보내지지 않는다.
- **모델은 «4 Argon», 사고 수준은 «보통»이다.** 사용자가 매번 고른 값이다. 새 대화는 «낮음»으로 시작하니(2026-10-20 두 번 확인) 보내기 전에 매번 «보통»을 고른다.
- **Claude Code 권한은 따로 할 것이 없다.** Chrome 툴은 자동 모드 분류기가 모두 승인했다(일곱 세션에서 프롬프트 0건). 허가 규칙을 넣으면 Gemini 말고 모든 사이트에 열리니 넣지 않는다.
- **이것만은 묻는다.** 검토 대상으로 지시받지 않은 저장소 파일(소스 코드 등)을 더 붙일지는 묻는다. 외부로 나가는 범위이기 때문이다.

## 시작

1. `tabs_context_mcp`에 `createIfEmpty`를 주어 새 탭을 연다. 사용자가 열어 둔 Gemini 탭은 보이지 않는다. 이 세션의 탭 그룹만 보인다.
2. `https://gemini.google.com/app`로 간다.
   - 항목마다 새 대화를 연다. 그래야 앞 답이 섞이지 않는다.
   - 옛 대화 URL(`/app/<id>`)은 가끔 `/app`, 즉 새 대화로 튕긴다. 열린 URL을 확인한다.
   - 이동 직후 `get_page_text`가 비어 있으면 3초 뒤 다시 읽는다.
3. 모델 선택기의 aria-label로 지금 모델을 확인한다.
   - 선택기 aria-label: «모드 선택 도구 열기, 현재 Argon 모드 사용 중»
   - 선택기 메뉴(2026-10-20 확인): 3.5 Flash-Lite · 3.8 Flash · 3.1 Pro · 4 Argon, 그 아래 «사고 수준»(낮음·보통·높음)
   - «4 Argon»과 «보통»을 고른다.
   - 메뉴는 JS `Escape` 이벤트로는 닫히지 않는다. 선택기를 다시 누른다.

## 첨부

1. «업로드 및 도구»(+) 메뉴를 연다.
2. 스크린샷을 한 번 찍는다. 메뉴를 연 직후에는 `find`가 자주 실패한다.
3. `find "input type=file"`로 찾은 첫 ref에 `file_upload`를 쓴다. 저장소 절대 경로를 그대로 쓴다.

함정:
- **업로드할 때마다 1~3을 다시 한다.** 한 번 올리면 ref가 무효가 된다(`Element is no longer in the document`).
- **한 메시지에 10장까지다.** 11장을 올리면 도구는 성공이라고 하는데, Gemini는 10장만 남긴다. 넘을 때는 메시지를 둘로 나눈다.
  - 첫 메시지: 10장과 «이번엔 «받음»이라고만 답해».
  - 둘째 메시지: 나머지 장과 진짜 질문.
- **크기는 `file_upload` 한 번에 10MB 미만이다.** PNG 5장(7.3MB)과, 이미지에 `.md`를 섞은 첨부는 문제없었다. 1MB가 넘는 PNG는 칩 이름이 `.jpg`로 표시된다.
- **첨부 수는 JS로 센다:** `document.querySelectorAll('img[alt=attachment]').length`
- **버튼은 좌표 말고 `find` ref로 누른다.** 첨부 썸네일 줄이 생기면 버튼 위치가 밀린다. 옛 좌표를 누르면 첨부 이미지 편집기가 열리는데, 왼쪽 위 (44,30)을 눌러 저장하지 않고 나온다.
- **`file://` URL은 navigate도 screenshot도 거부된다**(safetyCheck). 로컬 그림은 브라우저로 열지 말고 바로 올린다.
- **file input을 끝내 못 찾으면 클립보드로 붙인다.** PowerShell `SetFileDropList`로 파일을 클립보드에 올리고 입력창에 `ctrl+v`를 누른다. 사용자 클립보드를 덮어쓰니 쓴 뒤에 알린다.

## 움직임 판정

- GIF는 올리면 정지 JPG 한 장이 된다. mp4로 보낸다.
- Gemini는 mp4를 1초에 1장씩 본다. 짧은 동작은 10배 느리게 만든다.
- mp4는 PATH의 python(3.12)에 있는 cv2로 만든다.
  - 코덱은 H.264이고 Windows Media Foundation 백엔드로 만든다: `cv2.VideoWriter(경로, cv2.CAP_MSMF, cv2.VideoWriter_fourcc(*"H264"), fps, 크기)`.
  - `mp4v`는 2026-10-20부터 업로드가 끝나지 않는다(썸네일이 계속 돈다). 기본 백엔드의 `avc1`은 openh264 DLL이 없어 실패하고, ffmpeg도 없다.
  - 10MB가 넘으면 필요한 영역만 잘라 낸다(예: 가운데 960×540).
- 프레임은 매 프레임(1/30초)을 쓴다. 자르는 간격이 애니메이션 주기와 어긋나면 같은 프레임만 찍힌다. 그러면 Gemini가 «고정»이라고 오판한다.

## 프롬프트 넣기

- `computer type`은 줄바꿈이 Enter가 되어 도중에 보내진다. 가짜 paste 이벤트(`ClipboardEvent`)는 무시된다.
- `.ql-editor.textarea`에 focus를 주고 `document.execCommand('insertText', false, text)`로 넣는다. 4,249자·72줄까지 문제없었다.
- `javascript_tool` 호출 사이에 `const` 변수는 남지 않는다. 긴 텍스트는 `window.__p`에 나눠 이어 담은 뒤 넣는다.
- 보내기 전에 입력창 텍스트와 원문의 SHA-256을 비교한다. 64자 hex를 반환하면 «Base64» 차단에 걸리니 `match: true/false`만 받는다.
- 화면 속 대상을 가리킬 때는 좌표만 주지 않는다. 좌표만 주면 이웃 유닛으로 잘못 잡는다. 팀·생김새를 함께 적고, 찾은 것을 먼저 말하게 한다.

## 응답 기다리기

- `button[aria-label*="중지"]`가 사라질 때까지 JS로 기다린다.
  - CDP 평가는 45초에 끊긴다. 38초 이하 루프로 나눠 부른다.
  - "없음" 확인은 JS로 한다. `find`는 못 찾으면 에러를 돌려준다.
- 같은 대화에 이어 보냈다면 마지막 답만 보고 판단하지 않는다. 직후의 마지막 답은 이전 답이라 끝난 것처럼 보인다. 보내기 전 `message-content` 개수를 적어 두고 늘었는지 본다.
- 걸린 시간:
  - 이미지 6~10장 검수: 1~3.5분
  - 첨부 9개에 11k자 답: 약 2분 16초
  - mp4 하나: 10~45초
  - 한도나 속도 제한 문구는 본 적 없다.
- batch 안의 screenshot이 «[Image omitted due to error]»로 오면 다시 찍는다.

## 답 가져오기

1. 답 DOM을 복제한다.
2. 출처 칩(`source-footnote`·`sources-carousel-inline`·`source-inline-chip`)을 지운다. 그대로 두면 «PNG + 1» 같은 칩 글자가 본문에 섞인다.
3. Markdown으로 바꿔 `window`에 둔다.
4. `javascript_tool` 반환은 약 1,100자에서 잘린다. 800자씩 `browser_batch`로 읽어 파일로 잇는다.
5. 저장한 파일과 화면 변환본의 SHA-256을 비교한다(`match: true/false`).

## 답을 믿는 법

- Gemini는 화면에 없는 근거(피격 반응, 틀린 시각)를 지어낸다. 채점은 좌표와 생김새 설명이 둘 다 맞는지로 한다.
- 오판이 나오면 먼저 우리가 보낸 자료(프레임 간격·자른 영역)를 의심한다.
