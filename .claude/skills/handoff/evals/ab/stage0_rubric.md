# 단계 0 분류 기준 v3 (계획서 `next/2026-10-14/r1.md` §6 단계 0의 3~5)

NAP 하나의 항목마다 아래 필드를 채운다. 목적은 "그 NAP가 없었다면 다음 세션이 이 정보를 어디서 얻을 수 있었나, 실제로 썼나"다.

## class — 정보의 출처 (R → M → G → N 순서로, 먼저 맞는 것)

**핵심 정보**(다음 세션이 그 항목에서 얻어야 하는 것) 자체가 있어야 그 분류다. 관련 자료만 있고 핵심은 없으면 그 분류가 아니다.

- **R 저장소·환경**: 핵심 정보가 아래 어디에 있다. 근거로 `경로:줄`, 커밋, 문서 경로를 적는다.
  - 그 NAP의 `head` 커밋 시점 저장소(`next/` 폴더는 제외)와 git 기록. 그 시점 작업 트리의 미커밋 변경(NAP 상태 스냅샷에 적힌 것, 이후 커밋으로 확인)도 포함한다. 새 세션도 같은 작업 트리에서 시작하기 때문이다
  - `gh`로 조회할 수 있는 외부 상태(PR 상태·본문)
  - 환경: 설치된 스킬·플러그인 문서와 훅. specgate는 `C:/Users/bhy99/.claude/plugins/cache/proj3/specgate/0.1.0/`(skills·commands·템플릿)와 `C:/Users/bhy99/proj/proj3/framework/`, PR 절차는 `C:/Users/bhy99/.claude/skills/open-pr/SKILL.md`. handoff 스킬 자체는 환경으로 치지 않는다(시험 대상이다)
  - 관례: 앞선 작업의 커밋·PR 본문에 같은 절차가 반복돼 있다(예: 결정 → SPEC → EV 표 승인 → red → 구현 → 앵커 이동 → 캡처 → PR)
- **M 메모리**: 핵심 정보가 그 NAP 시점에 있던 메모리 파일(작업 지시에 목록이 있다)에 있다. 근거: 메모리 파일 이름.
- **G 사용자 메모**: 핵심 정보가 사용자 메모(`/handoff` 인자)에 있다. 모든 실험 조건이 받는 정보다.
- **N NAP에만**: 위 어디에도 핵심 정보가 없다. N에는 `origin`을 붙인다.
  - **사실**: 세션 밖에서 온 것. 사용자 발화(결정·선호·미룬 것), 명령 출력·시험 결과·실패한 시도, 세션에서 겪어 알게 된 도구·환경의 동작(함정·요령). 다음 세션은 사용자에게 다시 묻거나 다시 겪어야 얻는다.
  - **생성**: Claude가 저장소·환경 자료로 만든 분석·제안·계획·질문. 다음 세션도 비슷한 것을 다시 만들 수 있다(똑같지는 않을 수 있다).
  - 섞였으면 사실 쪽이다. 사실인지 생성인지 애매하면 생성이다(입증 책임은 스킬에 있다, 계획서 원칙 1).

판단 예:
- "2.20 성곽은 두 커밋(`7b14c16`, `e17fbd3`)으로 끝났다" → R(git log)
- "`battle.gd`는 작업 트리에서 CRLF라 문자열 치환 스크립트가 파일마다 줄바꿈을 맞춰야 한다" → 커밋 blob이 LF라 저장소로는 모르면 N, 사실(겪어서 안 함정)
- "읽을 파일: `SPEC.md:97-98`" → R, type 포인터
- "PR 병합은 Claude가 직접 한다" → 그 시점 메모리에 `pr-merge-by-claude.md`가 있으면 M
- "캡처 방법: 좌표 변환식·`frame_post_draw`·`blit_rect`" → 메모리에 다른 방식만 있으면 N, 사실(시험해 알아낸 요령)
- "질문: 집은 누가 놓나(근거 SPEC I1·S80·S43)" → 질문은 SPEC으로 Claude가 만든 것이면 N, 생성
- "임시 수치 제안 100/10/30" → N, 생성
- "`mark done`을 브랜치 전환 전에 하면 전환이 막힌다"(겪지 않고 저장소 상태로 추론한 함정) → N, 생성
- "사용자가 «플레이어가 짓는다»로 정했다"(SPEC에 아직 없음) → N, 사실
- "사용자가 2.19는 건너뛰자고 했다" → 메모에 있으면 G, 아니면 N, 사실

## wrong — 틀렸거나 낡았나 (true/false)

저장소 `head`, 다음 세션 기록, 이후 커밋과 대조한다. 다음 세션 시점에 이미 사실이 아니거나 행동을 잘못 이끄는 항목이면 true다(예: 한 번 거부된 일을 "항상 못 한다"로 적은 것). ⚠️로 표시된 추정도 틀린 것으로 드러나면 true다(집계에서 ⚠️ 여부를 따로 센다). note에 근거를 적는다.

## used — 다음 세션이 썼나 (N 항목과 wrong=true 항목만 판정, 나머지는 "-")

- **U**: 다음 세션 기록에서 그 항목 때문에 계획·행동이 달라졌거나 그 항목대로 행동했다. 예: 항목을 언급했다, 항목이 경고한 함정을 피했다, 항목의 결정대로 구현했다, 항목의 질문을 사용자에게 물었다. `used_evidence`에 `[MM-DD HH:MM] 인용`을 적는다.
- **-**: 쓰지 않았거나 필요 없었다.
- **?**: 기록만으로는 판단할 수 없다. 애매하면 ?다(N∧U로 세지 않는다).

## carried — 앞 NAP에서 넘어왔나 (true/false)

바로 앞 NAP(작업 지시에 경로가 있다)에 같은 뜻의 항목이 있으면 true다. 첫 NAP는 모두 false다.

## type

상태 / 결정 / 기각 / 함정 / 다음행동 / 질문 / 포인터 / 기타 중 하나.

## 출력 형식

JSON 배열을 쓴다. 항목 파일의 순서와 개수를 그대로 따른다. `origin`은 N일 때만 "사실"이나 "생성", 나머지는 "".

```json
[{"id": 1, "text": "<항목 앞부분 80자>", "class": "N", "origin": "사실", "wrong": false, "used": "U", "carried": false,
  "type": "함정", "evidence": "<경로:줄·커밋·메모리 파일, 60자 이내>", "used_evidence": "[10-13 19:13] ...", "note": ""}]
```
